# Wireless Attacks & WPA/WPA2 Cracking

## The Big Picture: How It All Works Together
In a typical Wi-Fi network, devices (clients) communicate with a wireless access point (AP). To secure this communication, networks use encryption like WPA/WPA2. When a client connects to a WPA/WPA2 network, a process called the **4-Way Handshake** occurs, which exchanges cryptographic keys used to encrypt subsequent traffic. 

A standard wireless attack involves manipulating the physical airwaves to capture this handshake. By forcing a client to disconnect (a **Deauthentication Attack**), the attacker waits for the client to automatically reconnect. During this reconnection, the attacker captures the **4-Way Handshake** packets from the air. Since the handshake contains a mathematical proof of the Wi-Fi password, the attacker can then use offline brute-force or dictionary attacks to crack the password.

```text
+----------+      (Deauth Packet)     +----------+
| Attacker | -----------------------> | Client   |
+----------+                          +----------+
     |                                     | (Client disconnects)
     |                                     v
     |   (Listens to airwaves)        +----------+
     |<===============================| Reconnect| (4-Way Handshake)
     |                                +----------+
     v                                     |
+----------+                               v
| Password |                          +----------+
| Cracker  |                          | Access   |
| (Offline)|                          | Point    |
+----------+                          +----------+
```

## Core Concepts

### Managed Mode vs. Monitor Mode
To capture packets not intended for us, our wireless network interface card (NIC) needs to change how it listens.

| Mode | Description | Analogy |
|---|---|---|
| **Managed Mode** | The default mode. The NIC only listens to packets explicitly addressed to its MAC address or broadcast packets. It ignores everything else. | Being in a crowded room but only listening when someone says your name. |
| **Monitor Mode** | The NIC listens to *all* wireless traffic on the configured channel, regardless of the destination MAC address. | Sitting in a crowded room and recording every single conversation you can hear. |

**Why it works:** Wi-Fi is a broadcast medium (radio waves). Unless encrypted, anyone in range can hear the traffic. Monitor mode simply tells your hardware/OS, "Don't discard packets meant for others; let me see them."

### WPA Keys and EAPOL (Extensible Authentication Protocol over LAN)
When a device connects to a WPA/WPA2 secured network, it doesn't just send the password in plain text. It performs a **4-Way Handshake** using the **EAPOL** protocol.

*   **Fact:** The password itself is never transmitted over the air.
*   **Fact:** The handshake exchanges cryptographic nonces (random numbers) and MAC addresses to derive a unique encryption key for the session (PTK - Pairwise Transient Key).
*   **Why it matters:** The EAPOL messages contain enough mathematical proof (a Message Integrity Code, or MIC) that an attacker can take the captured handshake offline. The attacker guesses a password, runs it through the same mathematical function with the captured nonces, and checks if the resulting MIC matches the one in the captured handshake.

### Deauthentication (Deauth) Attack
A Deauth attack is a type of Denial of Service (DoS) attack on a wireless network.
*   **Mechanism:** The attacker spoofs the MAC address of the Access Point (AP) and sends a "Deauthentication" frame to the client, effectively saying, "I am the router, you need to disconnect."
*   **Purpose in Pentesting:** We don't just want to annoy the user; we want them to reconnect so we can capture the **EAPOL** 4-way handshake.
*   **Note:** This works because management frames (like Deauth) were traditionally unencrypted and unauthenticated in standard 802.11 networks.

## The Aircrack-ng Suite: Tools & Workflow

The `aircrack-ng` suite is a collection of tools for assessing Wi-Fi network security. We focus on four main tools, understanding their purpose in the attack lifecycle.

1.  **airmon-ng:** (Purpose: Interface Preparation) Used to enable **Monitor Mode** on wireless interfaces.
2.  **airodump-ng:** (Purpose: Reconnaissance & Capture) Used to capture raw 802.11 frames. It lists available APs and clients, and saves the captured data (including handshakes) to a file.
3.  **aireplay-ng:** (Purpose: Traffic Injection) Used to inject frames into the network, most commonly to perform **Deauth attacks**.
4.  **aircrack-ng:** (Purpose: Cryptanalysis) Used to crack the WPA/WPA2 Pre-Shared Key (PSK) using the captured handshake and a wordlist (dictionary attack).

## Hands-On Practice (Authorized Lab Environment)

*Disclaimer: Assume these actions are performed against an authorized, self-owned lab network.*

### Step 1: Enable Monitor Mode (`airmon-ng`)

*   **Command:** `sudo airmon-ng start wlan0`
    *   *wlan0* is your wireless interface name.
*   **Observation:** The command will typically create a new virtual interface, often named `wlan0mon`, which is now in Monitor Mode.
*   **Cleanup Note:** Some background processes (like NetworkManager) can interfere. It's best practice to run `sudo airmon-ng check kill` before starting monitor mode.

### Step 2: Reconnaissance (`airodump-ng`)

*   **Command (General sweep):** `sudo airodump-ng wlan0mon`
    *   This shows all APs nearby. Identify your target AP's **BSSID** (MAC address) and **Channel (CH)**.
*   **Command (Targeted capture):** `sudo airodump-ng -c 6 --bssid 11:22:33:44:55:66 -w capture_file wlan0mon`
    *   `-c 6`: Listens *only* on channel 6 (prevents missing packets while hopping channels).
    *   `--bssid`: Filters traffic only for the target AP.
    *   `-w capture_file`: Saves captured packets to files named `capture_file.*` (specifically the `.cap` file is important).

### Step 3: Force the Handshake (`aireplay-ng`)

While `airodump-ng` is running in one terminal window, open another terminal to send the Deauth attack.

*   **Command:** `sudo aireplay-ng --deauth 10 -a 11:22:33:44:55:66 -c AA:BB:CC:DD:EE:FF wlan0mon`
    *   `--deauth 10`: Sends 10 deauthentication frames. (Don't send an infinite amount; we want them to reconnect).
    *   `-a`: The BSSID of the Access Point.
    *   `-c`: The MAC address of the target client (found in the `airodump-ng` output).
*   **Result:** Look at your running `airodump-ng` window. In the top right corner, you should see `[ WPA handshake: 11:22:33:44:55:66 ]`. This means you successfully captured the EAPOL packets!

### Step 4: Crack the Password (`aircrack-ng`)

Now that you have the handshake in `capture_file.cap`, you can stop monitoring and crack it offline.

*   **Command:** `aircrack-ng -w /usr/share/wordlists/rockyou.txt capture_file.cap`
    *   `-w`: Specifies the wordlist (dictionary) file to use.
*   **How it works:** `aircrack-ng` will calculate the MIC for every password in the wordlist and compare it to the captured MIC. If a match is found, the password is revealed.

## Real-Time Technical Scenario

**Scenario:** A SOC analyst notices repeated disconnections from a critical executive's laptop on the corporate Wi-Fi, followed by immediate reconnections.
**Analysis:** The analyst investigates the wireless controller logs and sees bursts of Deauthentication frames spoofing the corporate AP's MAC address, directed at the executive's laptop.
**Conclusion:** This is a classic Deauth attack. An attacker in the building's lobby or parking lot is likely trying to capture the WPA2 4-way handshake to crack the network password offline. The SOC initiates a physical security sweep of the perimeter to locate the rogue device and forces a complex password rotation for the Wi-Fi.
