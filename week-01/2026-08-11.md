## 1. What is it?
This session covers the foundational elements of how networks operate and how attackers systematically analyze them.
- **Cyber Kill Chain**: A **7-phase framework** by Lockheed Martin describing the lifecycle of a cyberattack.
- **Reconnaissance**: The process of gathering intelligence on a target. **Passive recon (OSINT)** uses public data without touching the target, while **Active recon** directly interacts with the target (e.g., scanning).
- **Core Protocols**: Standardized rules for communication:
  - **TCP (Transmission Control Protocol) & UDP (User Datagram Protocol)**: Layer 4 transport protocols. TCP is reliable; UDP is fast.
  - **DNS (Domain Name System)**: Translates human-readable domain names into IP addresses.
  - **DHCP (Dynamic Host Configuration Protocol)**: Automatically assigns IP addresses to devices.
  - **SSH (Secure Shell)**: An encrypted protocol for remote system management, replacing the insecure Telnet.
- **IP Addressing & Subnetting**: Logical addresses (IPv4/IPv6) assigned to devices, and the process of dividing large networks into smaller, efficient sub-networks (CIDR/Subnetting).
- **Enumeration**: Phase 1 of active reconnaissance, where an attacker extracts detailed information (usernames, shares, banners) from discovered services.

## 2. Why does it happen?
Why do networks require these protocols, and why do vulnerabilities exist within them?
- **Protocol Necessity**: Devices need standard rules to communicate. IP routes packets, DHCP automates addressing to avoid manual errors, DNS makes browsing user-friendly, and NAT exists to solve the **IPv4 exhaustion problem** (we ran out of the ~4.3 billion L3 addresses).
- **Security Deficits (Legacy vs. Modern)**: Older protocols (Telnet, FTP) prioritized functionality and send data in **plaintext**. They exist because they were built before the modern threat landscape. Vulnerabilities often happen due to **misconfigurations**—like allowing anonymous FTP access or SMB null sessions—which administrators leave open for ease of access, unknowingly expanding the attack surface.
- **Why the Kill Chain**: Attackers follow structured methodologies because blind attacks usually fail. Proper reconnaissance dictates successful exploitation.

## 3. How does it work?

### The Cyber Kill Chain
1. **Reconnaissance**: Gather info (OSINT, scanning).
2. **Weaponization**: Build the payload.
3. **Delivery**: Send the payload (email, web, USB).
4. **Exploitation**: Trigger the vulnerability.
5. **Installation**: Install persistent malware/backdoor.
6. **Command & Control (C2)**: Establish remote control.
7. **Actions on Objectives**: Steal data, ransomware, destroy.

### TCP vs. UDP
| Feature | TCP | UDP |
|---------|-----|-----|
| Connection | Connection-oriented (3-way handshake) | **Connectionless** |
| Reliability | ✅ Guaranteed delivery, ordered | ❌ No guarantee, unordered |
| Speed | Slower | ✅ Faster |
| Use Cases | HTTP, SSH, FTP, Email | DNS, DHCP, VoIP, Streaming |

**TCP 3-Way Handshake (How connection is established):**
```text
Client  ──── SYN ────►  Server
Client  ◄─ SYN/ACK ──  Server
Client  ──── ACK ────►  Server
        (connection established)
```
> **Note on TCP Security:** TCP ensures data *arrives intact*, but it provides **no encryption**. Anyone on the network can read it. TLS must be layered on top (e.g., HTTPS) for real security.

### DHCP (DORA Process)
DHCP operates on UDP ports 67 (Server) / 68 (Client).
```text
Client                                Server
  │──── 1. DISCOVER (broadcast) ───────►│ "I need an IP!"
  │◄─── 2. OFFER ──────────────────────│ "I can offer 192.168.1.10"
  │──── 3. REQUEST (broadcast) ────────►│ "I accept 192.168.1.10"
  │◄─── 4. ACKNOWLEDGE ────────────────│ "Confirmed! It's yours."
```

### DNS Resolution Flow
DNS operates primarily on UDP port 53 (TCP is used for zone transfers).
```text
You type: google.com
   │
   ▼
1. Browser Cache (Fastest)
   │ (not found)
   ▼
2. OS Cache / hosts file
   │ (not found)
   ▼
3. Recursive Resolver (ISP or 8.8.8.8)
   │ (not cached)
   ▼
4. Root Server (.) -> 5. TLD Server (.com) -> 6. Authoritative Server
   │
   ▼
Returns IP to Resolver -> Browser connects.
```

### IP Addressing & Subnetting
- **Logical (IP)**: Layer 3, routable (e.g., `192.168.1.1`).
- **Physical (MAC)**: Layer 2, burned into hardware (e.g., `AA:BB:CC:DD:EE:FF`). **ARP** maps IP to MAC.
- **IPv4**: 32-bit (4 octets). Uses NAT to share public IPs.
- **IPv6**: 128-bit (hex). Huge address space, mandatory IPSec, no NAT needed.

**Subnetting/CIDR**:
Dividing a network shrinks **broadcast domains**, reducing congestion and increasing security. Instead of strict Classes (A, B, C), **CIDR** uses prefix lengths.
- `/24` = 254 usable hosts.
- Formula for hosts: **2^h - 2** (h = host bits). We subtract 2 because the **Network Address** (first IP) and **Broadcast Address** (last IP) cannot be assigned.

### SSH Authentication (Key Pairs)
SSH (Port 22) uses asymmetric encryption for authentication, then symmetric encryption for the session.
1. Client holds a **private key** (secret).
2. Server holds the corresponding **public key** (lock).
3. Client proves it holds the private key; server grants access without a password.

## 4. Where is it used / found?
- **DNS**: Found everywhere on the internet to resolve names.
- **DHCP**: Found on home routers, enterprise gateways, and domain controllers to assign IPs.
- **NAT / PAT**: Found on network edges (routers/firewalls) translating private internal IPs to a public IP.
- **SSH**: The standard for Linux server administration, secure file transfers (SFTP/SCP), and DevOps automation.
- **SMB**: Used in Windows environments for file and printer sharing.

## 5. How do I identify it?
Identify protocols via their default **port numbers** and behaviors:
| Port | Protocol | Service | Identification / Indicator |
|------|----------|---------|-----------------------------|
| 20/21| TCP      | FTP     | Banner grabbing reveals software version (e.g., vsftpd). Check for Anonymous login. |
| 22   | TCP      | SSH     | Connection prompt. Key exchange packets. |
| 23   | TCP      | Telnet  | Plaintext connection. High risk. |
| 25   | TCP      | SMTP    | Responds to VRFY/EXPN commands. |
| 53   | UDP/TCP  | DNS     | Port 53 traffic. UDP for standard queries, TCP for large responses/Zone Transfers. |
| 80/443| TCP     | HTTP/S  | Web traffic. Use `whatweb` to identify CMS/Stack. |
| 139/445| TCP    | SMB     | Windows file sharing. Try null sessions (`smbclient -N`). |

**Identifying IPs:**
- **Class A**: `1.x.x.x` to `126.x.x.x` (Private: `10.0.0.0/8`)
- **Class B**: `128.x.x.x` to `191.x.x.x` (Private: `172.16.0.0/12`)
- **Class C**: `192.x.x.x` to `223.x.x.x` (Private: `192.168.0.0/16`)
- **Loopback**: `127.0.0.1` (IPv4) or `::1` (IPv6). Used to test the local TCP/IP stack.

## 6. Hands-on / Lab Methodology
When performing authorized enumeration on a network:
- **What to observe first:** The active IP addresses on the subnet.
- **Attack surface:** The open ports and running services on those IPs.
- **Initial hypothesis:** Services might be outdated (vulnerable to CVEs) or misconfigured (default credentials, anonymous access).
- **What to test:**
  1. **Port Scan**: `nmap -sV -sC -A <target>` to map services.
  2. **FTP Enum**: Check for anonymous login (`nmap --script ftp-anon -p 21 <target>`).
  3. **SMB Enum**: Dump users and shares using `enum4linux -a <target>`.
  4. **Web Enum**: Fuzz directories using `gobuster` or `ffuf`.
- **How to test it safely (authorized lab):** Only target IP addresses in your explicit scope. Control nmap timing (`-T3` or `-T4`) to avoid crashing legacy hardware.
- **Expected result:** A detailed list of valid usernames, software versions, open file shares, and hidden web directories.
- **How to interpret the result:** Use the gathered info to formulate an exploit strategy (Phase 4 of Kill Chain), such as credential stuffing or exploiting a specific software version.

## 7. Failed Attempts & Why
- **What was tried:** Running `nmap -sS` against a DNS server to find open UDP port 53.
- **Why it failed:** `-sS` is a TCP SYN scan. UDP is connectionless and does not respond to SYN packets.
- **What that tells us:** You must match the tool/scan type to the protocol.
- **What to try next:** Use `-sU` for UDP scanning.

- **What was tried:** Logging into SMB as `anonymous`.
- **Why it failed:** SMB doesn't use the username `anonymous` for unauthenticated access; it uses a blank username and blank password (Null Session).

## 8. Example
**Scenario:** A penetration tester targets a corporate web server.
1. **Passive Recon (OSINT):** The tester looks up DNS records and finds the IP address.
2. **Active Recon (Scanning):** They run `nmap` and find TCP 21 (FTP), 22 (SSH), and 80 (HTTP) open.
3. **Enumeration:** Testing port 21 reveals **Anonymous FTP** is enabled.
4. **Exploitation:** The tester logs into FTP without a password, downloads a configuration file, finds a plaintext SSH password, and uses it to log into port 22, gaining full system control.

## 9. Impact
- **SYN Flood (TCP)**: Sends thousands of SYN packets, leaving connections half-open, exhausting server resources resulting in **Denial of Service (DoS)**.
- **Cleartext Protocols (Telnet/FTP)**: Susceptible to **Man-in-the-Middle (MitM)** attacks where credentials are sniffed.
- **DNS Cache Poisoning / Spoofing**: Injecting fake DNS records redirects legitimate traffic to attacker-controlled phishing servers.
- **DNS Zone Transfer (AXFR)**: Misconfiguration allowing an attacker to dump the *entire* domain's DNS records, mapping the whole infrastructure.

## 10. Detection
How defenders/SOC analysts detect these activities:
- **Recon/Scanning**: IDS/IPS (like Snort) trigger alerts on high-frequency connection attempts across multiple ports (Nmap sweeps).
- **Brute-Force**: SIEMs flag multiple failed login attempts on SSH (Port 22) or SMB (Port 445) from a single IP.
- **DNS Anomalies**: Unusually large DNS responses indicate a **DNS Amplification (DDoS)** attack. Requests for `AXFR` (Zone Transfers) from unauthorized IPs trigger critical alerts.

## 11. Prevention / Remediation
- **Secure Remote Access**: Never use Telnet. Harden SSH by disabling password authentication, enforcing key-based auth, changing the default port, disabling root login (`PermitRootLogin no`), and using `fail2ban`.
- **Network Segmentation**: Use Subnetting/VLANs to separate sensitive departments. This shrinks broadcast domains and limits lateral movement.
- **Service Configuration**: 
  - Disable Anonymous FTP.
  - Disable SMB Null Sessions.
  - Restrict DNS Zone Transfers to trusted slave servers only.
- **DNS Security**: Implement **DNSSEC** (digitally signs records to prevent spoofing).

## 12. Related Concepts
- **OSINT -> Cyber Kill Chain**: OSINT is the primary tool for the Reconnaissance phase (Phase 1).
- **IP/MAC -> ARP -> DORA**: To get on a network, a device uses its MAC to complete the DHCP DORA process to get an IP. To talk to local devices, it uses ARP to resolve IPs back to MACs.
- **IPv4 Exhaustion -> NAT/PAT & IPv6**: Because IPv4 addresses ran out, NAT (specifically PAT) was created to map many private IPs to one public IP using port numbers. IPv6 was created to solve this permanently.

## 13. Important Commands / Syntax

**Nmap (Scanning):**
- `nmap -sV target` (Detect service versions)
- `nmap -sC target` (Run default enumeration scripts)
- `nmap -sU target` (UDP scan)

**SSH (Secure Shell):**
- `ssh-keygen -t ed25519` (Generate a secure key pair)
- `ssh -i ~/.ssh/key.pem user@ip` (Connect using private key)
- `ssh -L 8080:localhost:80 user@ip` (Local port forwarding/tunneling)

**SMB & FTP (Enumeration):**
- `enum4linux -a target` (Full SMB dump of users, groups, shares)
- `smbclient -L //target -N` (Check for null session shares)
- `nc -nv target 21` (Banner grabbing via Netcat)

**DNS:**
- `dig axfr @ns1.target.com target.com` (Attempt DNS Zone Transfer)

## 14. Interview Questions

**Q: Explain the difference between Active and Passive Reconnaissance.**
> Passive recon (OSINT) gathers public data without interacting with the target, leaving no logs. Active recon involves probing the target directly (e.g., port scanning) and can be detected.

**Q: What is the difference between TCP and UDP, and when would you use UDP?**
> TCP requires a 3-way handshake and guarantees reliable, ordered delivery. UDP is connectionless and offers no delivery guarantees. UDP is used when speed is more critical than reliability (e.g., DNS queries, VoIP, live streaming).

**Q: Is TCP secure?**
> No. TCP is *reliable*, but not secure. It provides no encryption or authentication. Unencrypted protocols running over TCP (like Telnet) can be intercepted via MitM attacks.

**Q: What is a Null Session in SMB?**
> An unauthenticated connection to a Windows SMB service. If misconfigured, it allows attackers to extract user lists, groups, and network shares without any credentials.

**Q: What is the difference between NAT and PAT?**
> NAT translates a private IP to a public IP. PAT (Port Address Translation / NAT Overload) translates *many* private IPs to a *single* public IP by using unique port numbers to track individual sessions.

## 16. Key Takeaways
- The **Cyber Kill Chain** always starts with Reconnaissance (Passive then Active).
- **Ports to memorize**: FTP (20/21), SSH (22), Telnet (23), SMTP (25), DNS (53), DHCP (67/68), HTTP/S (80/443), SMB (139/445).
- **TCP** uses a 3-way handshake (SYN, SYN/ACK, ACK). **UDP** is connectionless.
- **DHCP** assigns IPs automatically via the DORA process.
- **DNS** translates names to IPs; `A` records are IPv4, `AAAA` are IPv6, `CNAME` is an alias.
- **Subnetting** reduces broadcast congestion; CIDR notation (`/24`) dictates the network bits.
- **Enumeration** extracts actionable intelligence (users, banners, misconfigs) from open ports. Tools like `nmap` scripts, `enum4linux`, and `netcat` are vital.
- Never use plaintext protocols like Telnet; always prefer **SSH** with key-pair authentication.

## 17. One-Minute Revision
**Reconnaissance** finds targets. **Scanning** (nmap) finds open ports (21, 22, 53, 80). **Enumeration** pulls data from those ports (anonymous FTP, SMB null sessions, DNS zone transfers). Attackers exploit these to advance the **Cyber Kill Chain**. Networks rely on **TCP/UDP** for transport, **DNS** for naming, **DHCP** for addressing, and **NAT** to conserve **IPv4** addresses. **Subnetting (CIDR)** divides networks for security and speed. Defenders stop this by hardening configs (no root SSH login, using key pairs), closing unused ports, and monitoring for scan patterns and brute-force attempts.

### 🧩 How It All Works Together (The Big Picture)
When an attacker targets a network, they follow the **Cyber Kill Chain**. They start with OSINT to gather intel, then move to Active Recon by scanning IP addresses and enumerating open TCP/UDP ports. Understanding core networking (DNS, DHCP, NAT) allows the attacker to map out the internal subnet. By enumerating misconfigured services (like Anonymous FTP or legacy SMB null sessions), the attacker discovers attack vectors to exploit, establishing a foothold and pivoting to their ultimate objective.
