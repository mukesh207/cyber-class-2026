## 🔫 Cyber Kill Chain

### What is it?
A **7-phase model** by Lockheed Martin that describes the steps an attacker follows to carry out a successful cyberattack.

| # | Phase | One-line meaning |
|---|-------|-----------------|
| 1 | **Reconnaissance** | Gather info about the target |
| 2 | **Weaponization** | Build the exploit/payload |
| 3 | **Delivery** | Send payload (email, USB, web) |
| 4 | **Exploitation** | Trigger the vulnerability |
| 5 | **Installation** | Install persistent malware |
| 6 | **Command & Control (C2)** | Remotely control the victim machine |
| 7 | **Actions on Objectives** | Steal data, drop ransomware, cause damage |

### 🎯 Interview Q&A

**Q: What is the Cyber Kill Chain?**
> A framework that breaks a cyberattack into 7 stages — from initial reconnaissance all the way to achieving the attacker's goal. It helps defenders identify where to detect or stop an attack early.

**Q: Why is Reconnaissance the most important phase for defenders?**
> Because it's the earliest phase. If defenders can detect or disrupt recon (e.g., detecting scans or limiting public info exposure), the attack never progresses further.

## 🔍 Reconnaissance

### Active vs. Passive

| | Passive | Active |
|-|---------|--------|
| Touches target? | ❌ No | ✅ Yes |
| Detectable? | ❌ No | ✅ Yes (leaves logs) |
| Examples | WHOIS, LinkedIn, Google | nmap, banner grabbing |

### OSINT
**Open Source Intelligence** — collecting data from **publicly available** sources only (legal, no interaction with target).
- Examples: WHOIS records, DNS lookups, social media, job postings, Google dorking

### 🎯 Interview Q&A

**Q: What is the difference between active and passive reconnaissance?**
> Passive recon collects info without ever touching the target — it's undetectable. Active recon directly interacts with target systems (e.g. port scanning) and can be logged or detected.

**Q: What is OSINT?**
> OSINT is gathering intelligence from publicly available sources like websites, social media, DNS records, and job postings — without any direct contact with the target.

## 🔢 Basic Port Numbers

> A **port** is a number that tells the OS which application or service a packet belongs to.

| Port | Protocol | Service |
|------|----------|---------|
| 20 / 21 | TCP | FTP (File Transfer) |
| 22 | TCP | SSH (Secure Shell) |
| 23 | TCP | Telnet |
| 25 | TCP | SMTP (Send email) |
| 53 | TCP/UDP | DNS |
| 67 / 68 | UDP | DHCP |
| 80 | TCP | HTTP |
| 110 | TCP | POP3 (Receive email) |
| 143 | TCP | IMAP |
| 443 | TCP | HTTPS |
| 3389 | TCP | RDP (Remote Desktop) |

> 💡 Port ranges: **0–1023** = well-known | **1024–49151** = registered | **49152–65535** = dynamic/ephemeral

### 🎯 Interview Q&A

**Q: What port does SSH run on?**
> Port **22**.

**Q: What is the difference between port 80 and port 443?**
> Port 80 is HTTP — unencrypted web traffic. Port 443 is HTTPS — encrypted with TLS/SSL. Always prefer 443 for security.

**Q: What port does DNS use and which protocol?**
> DNS uses port **53**. It uses **UDP** for normal queries (fast) and **TCP** for zone transfers (reliable).

## 🔀 TCP vs. UDP

| Feature | TCP | UDP |
|---------|-----|-----|
| Connection | Connection-oriented (3-way handshake) | **Connectionless** |
| Reliability | ✅ Guaranteed delivery | ❌ No guarantee |
| Order | ✅ In-order delivery | ❌ No ordering |
| Speed | Slower | ✅ Faster |
| Use cases | HTTP, FTP, SSH, Email | DNS, DHCP, VoIP, Video streaming |

> ⚠️ **Key point:** UDP is **connectionless** — it fires packets at the destination with no setup, no handshake, and no confirmation that they arrived.

### TCP 3-Way Handshake
```
Client  ──── SYN ────►  Server
Client  ◄─ SYN/ACK ──  Server
Client  ──── ACK ────►  Server
        (connection established)
```

### 🧠 Remember
**SYN, SYN/ACK, ACK** (Synchronize, Synchronize-Acknowledge, Acknowledge). Think of it as a phone call: "Hello?" -> "I hear you, Hello?" -> "I hear you too, let's talk."

### 💡 Common Mistake
TCP guarantees *delivery*, not *security*. A Man-in-the-Middle can still read your TCP packets if TLS (encryption) is not used.

### 🔐 Is TCP Secure?

**Short answer: TCP is reliable — NOT secure.**

| What TCP provides | What TCP does NOT provide |
|-------------------|--------------------------|
| ✅ Ordered delivery | ❌ Encryption |
| ✅ Error checking (checksum) | ❌ Authentication |
| ✅ Retransmission of lost packets | ❌ Confidentiality |
| ✅ Connection confirmation (handshake) | ❌ Protection from eavesdropping |

> TCP only ensures data **arrives correctly and in order** — anyone on the network can still **read or tamper** with it.
> For real security, **TLS is layered on top of TCP** → that's how **HTTPS** works (HTTP + TLS over TCP port 443).

#### TCP Vulnerabilities
| Attack | How it works |
|--------|-------------|
| **SYN Flood** | Attacker sends thousands of SYN packets, never completes handshake → server exhausts resources |
| **TCP Session Hijacking** | Attacker intercepts a session and injects packets using predicted sequence numbers |
| **Man-in-the-Middle (MitM)** | Without encryption, attacker can read/modify traffic between client and server |

---

### 📦 Real-World Applications

#### TCP — used when data must arrive correctly
| Application | Why TCP? |
|-------------|----------|
| **HTTP / HTTPS** (web browsing) | A missing byte would corrupt the page |
| **Email** (SMTP, IMAP, POP3) | Every word of an email must arrive intact |
| **SSH** (remote login) | Commands must be accurate — a missing char breaks everything |
| **FTP** (file transfer) | Files would be corrupted if packets were lost |
| **Database queries** | Data integrity is critical |

#### UDP — used when speed matters more than perfection
| Application | Why UDP? |
|-------------|----------|
| **Video streaming** (YouTube, Netflix) | A dropped frame is fine — buffering is worse |
| **VoIP** (WhatsApp calls, Zoom audio) | Slight loss is acceptable; delay is not |
| **Online gaming** | Low latency beats perfect delivery |
| **DNS lookups** | Quick single query/response — no need for a full connection |
| **DHCP** | IP assignment at boot — speed matters |
| **Live broadcasts** | Real-time — can't wait for retransmission |

---

### 🎯 Interview Q&A

**Q: What is the difference between TCP and UDP?**
> TCP is connection-oriented — it uses a 3-way handshake and guarantees reliable, ordered delivery. UDP is connectionless — it sends packets without establishing a connection, so it's faster but with no delivery guarantee.

**Q: When would you use UDP over TCP?**
> When speed matters more than reliability — like live video streaming, VoIP calls, or online gaming. A dropped frame is better than a delayed one.

**Q: Is TCP secure?**
> No — TCP is **reliable but not secure**. It guarantees delivery and ordering, but it does not encrypt or authenticate data. Anyone on the network can read or tamper with TCP traffic. For security, **TLS is added on top of TCP** (e.g. HTTPS = HTTP over TLS over TCP).

**Q: What is a SYN Flood attack?**
> An attacker sends a massive number of SYN packets to a server but never completes the 3-way handshake. The server keeps half-open connections waiting, exhausting its resources — a form of **DoS (Denial of Service)** attack.



## 🔁 DTP — Data Transfer Process (FTP)

### What is it?
**DTP (Data Transfer Process)** is a specific component of the **FTP (File Transfer Protocol)** architecture, responsible for the actual movement of data between a client and a server. It is not a standalone universal protocol like TCP or UDP.

### How it works in FTP
FTP uses **two separate connections**:

| Connection | Port | Purpose |
|------------|------|---------|
| **Control connection** | 21 | Sends commands (login, list files, etc.) |
| **Data connection (DTP)** | 20 | Actually transfers the file data |

### Two Modes of Data Transfer

| Mode | How it works |
|------|-------------|
| **Active mode** | Server initiates the data connection back to the client on port 20 |
| **Passive mode** | Client initiates both connections — used when client is behind a firewall/NAT |

> 💡 **Passive mode** is more firewall-friendly because the client always initiates — no inbound connection needed from the server.

### 🎯 Interview Q&A

**Q: What is DTP?**
> DTP (Data Transfer Protocol) is the component responsible for the actual transfer of data between client and server — most notably used in FTP, where it handles the data channel separately from the command channel.

**Q: What are the two connections in FTP?**
> FTP uses a **control connection** (port 21) for commands and a **data connection** (port 20, via DTP) for the actual file transfer.

**Q: What is the difference between active and passive FTP mode?**
> In **active mode**, the server opens the data connection back to the client — which can be blocked by firewalls. In **passive mode**, the client opens both connections, making it firewall-friendly.

## 🌐 DNS — Domain Name System

### What is DNS?
DNS is the **phonebook of the internet**. Computers communicate using **IP addresses** (e.g. `142.250.182.46`), but humans use domain names (e.g. `google.com`). DNS translates human-readable domain names → IP addresses.

> Without DNS, you'd have to memorise IP addresses to visit every website.

---

### What Does DNS Do?

| Function | Description |
|----------|-------------|
| **Name Resolution** | Converts `google.com` → `142.250.182.46` |
| **Reverse Lookup** | Converts an IP → domain name |
| **Mail routing** | MX records tell email where to go |
| **Load balancing** | Multiple IPs for one domain — spreads traffic |
| **Service discovery** | SRV records point to specific services |

---

### How DNS Works — Step by Step

```
You type: google.com
               │
               ▼
    ┌─────────────────────┐
    │  1. Browser Cache   │ ← checked first (fastest)
    └─────────┬───────────┘
              │ not found
              ▼
    ┌─────────────────────┐
    │  2. OS Cache /      │ ← checks /etc/hosts file
    │     hosts file      │
    └─────────┬───────────┘
              │ not found
              ▼
    ┌─────────────────────┐
    │  3. Recursive       │ ← your ISP's or configured DNS
    │     Resolver        │   (e.g. Google 8.8.8.8)
    └─────────┬───────────┘
              │ not found in resolver cache
              ▼
    ┌─────────────────────┐
    │  4. Root Name       │ ← knows who handles .com, .org, etc.
    │     Server (.)      │
    └─────────┬───────────┘
              │ "ask the .com TLD server"
              ▼
    ┌─────────────────────┐
    │  5. TLD Name Server │ ← handles .com domains
    │     (.com)          │
    └─────────┬───────────┘
              │ "ask google's authoritative server"
              ▼
    ┌─────────────────────┐
    │  6. Authoritative   │ ← google's own DNS server
    │     Name Server     │   has the actual answer
    └─────────┬───────────┘
              │ returns IP: 142.250.182.46
              ▼
    Resolver caches it → Browser connects to IP
```

> 💡 **TTL (Time To Live):** Every DNS record has a TTL — how long (in seconds) a resolver should cache the answer before asking again.

---

### DNS Record Types

| Record | Full Name | What it does |
|--------|-----------|-------------|
| **A** | Address | Maps a domain → **IPv4** address |
| **AAAA** | Quad-A | Maps a domain → **IPv6** address |
| **CNAME** | Canonical Name | Alias — points one domain to **another domain** |
| **MX** | Mail Exchange | Points to the mail server for a domain |
| **TXT** | Text | Stores arbitrary text — used for SPF, DMARC, verification |
| **NS** | Name Server | Specifies which DNS server is authoritative for the domain |
| **PTR** | Pointer | Reverse DNS — IP → domain name |
| **SOA** | Start of Authority | Stores admin info about a DNS zone |
| **SRV** | Service | Points to a specific service/port (e.g. SIP, XMPP) |

---

### Record Deep-Dives

#### 🔵 A Record (IPv4)
- Maps a **hostname → IPv4 address**
- Most common record type
```
google.com.    300    IN    A    142.250.182.46
```
> `google.com` → `142.250.182.46` (connect here)

#### 🟣 AAAA Record (IPv6)
- Same as A record but for **IPv6 addresses**
- IPv6 = 128-bit address (8 groups of 4 hex digits)
```
google.com.    300    IN    AAAA    2404:6800:4009:825::200e
```
> Used when the client and server both support IPv6

#### 🟡 CNAME Record (Alias)
- Points a domain to **another domain name** (not an IP directly)
- The resolver then looks up the target domain to get the IP
```
www.google.com.    300    IN    CNAME    google.com.
```
> `www.google.com` → `google.com` → (A record) → IP
> ⚠️ **CNAME cannot coexist with other records at the root domain** (e.g. can't put CNAME on `google.com` itself — only subdomains)

#### 🔴 MX Record (Mail)
- Tells email servers where to deliver mail for a domain
- Has a **priority number** — lower = higher priority
```
google.com.    300    IN    MX    10    smtp.google.com.
```

---

### Google DNS

| DNS Server | IP Address |
|------------|-----------|
| **Google Primary** | `8.8.8.8` |
| **Google Secondary** | `8.8.4.4` |
| **Google IPv6 Primary** | `2001:4860:4860::8888` |
| **Google IPv6 Secondary** | `2001:4860:4860::8844` |

- Google's public DNS is fast, reliable, and globally distributed
- Commonly used as an alternative to your ISP's DNS
- Other popular public DNS: **Cloudflare** `1.1.1.1`, **OpenDNS** `208.67.222.222`

> 💡 **Why change DNS?** ISP DNS can be slow, log your queries, or be blocked. Google/Cloudflare DNS is faster and more private.

---

### DNS Security Concerns

| Attack | What happens |
|--------|-------------|
| **DNS Spoofing / Cache Poisoning** | Attacker injects fake DNS responses → users sent to malicious IPs |
| **DNS Hijacking** | Attacker changes DNS settings to redirect traffic |
| **DNS Amplification (DDoS)** | Attacker sends small DNS queries with spoofed source IP → large responses flood the victim |
| **DNS Zone Transfer** | If misconfigured, attacker can dump all DNS records (`dig AXFR`) |

> 🔐 **DNSSEC** (DNS Security Extensions) — digitally signs DNS records to prevent spoofing

---

### 🎯 Interview Q&A

**Q: What is DNS and what does it do?**
> DNS (Domain Name System) is the internet's phonebook — it translates human-readable domain names like `google.com` into IP addresses that computers use to communicate.

**Q: Explain how DNS resolution works.**
> When you type a domain, the browser checks its cache first, then the OS cache, then asks a recursive resolver (e.g. 8.8.8.8). If the resolver doesn't have it cached, it asks a root server → TLD server → authoritative name server, which returns the IP. The resolver caches the result for future queries.

**Q: What is the difference between an A record and a AAAA record?**
> An **A record** maps a domain to an **IPv4** address. A **AAAA record** maps a domain to an **IPv6** address. AAAA is used when both sides support IPv6.

**Q: What is a CNAME record?**
> A CNAME (Canonical Name) is an alias — it maps one domain to another domain name instead of directly to an IP. The resolver then looks up the target domain. Example: `www.google.com` → CNAME → `google.com` → A record → IP.

**Q: What is Google's DNS server IP?**
> Google's primary DNS is `8.8.8.8` and secondary is `8.8.4.4`.

**Q: What is DNS Cache Poisoning?**
> An attacker injects fake/malicious DNS records into a resolver's cache. When users query that resolver, they get the wrong IP and are redirected to a malicious site — even though they typed the correct domain.

**Q: What is a DNS Zone Transfer and why is it a security risk?**
> A zone transfer (`AXFR`) is a way to replicate all DNS records from one name server to another. If misconfigured and publicly accessible, an attacker can dump the entire DNS database of a domain — revealing all subdomains, IPs, and infrastructure.

**Q: What is TTL in DNS?**
> TTL (Time To Live) is the value (in seconds) that tells a resolver how long to cache a DNS record before requesting a fresh one.

## 📡 DHCP — Dynamic Host Configuration Protocol

### What is DHCP?
DHCP is a **network protocol** that **automatically assigns IP addresses** and other network configuration (subnet mask, gateway, DNS) to devices when they join a network.

> Without DHCP, every device would need its IP address configured **manually**.

### Where Does DHCP Run?
- Runs on a **DHCP server** — this can be:
  - A dedicated server (Windows Server, Linux)
  - A **router / gateway** (most home routers act as DHCP servers)
  - A network switch (Layer 3)
- Uses **UDP** — port **67** (server) and port **68** (client)

### Main Goal
> Automatically assign a unique IP address + network config to every device on a network — no manual setup needed.

---

### 🔄 DORA Process — How DHCP Works

DHCP uses a **4-step handshake** called **DORA**:

```
Client                                Server
  │                                     │
  │──── 1. DISCOVER (broadcast) ───────►│  "Anyone out there? I need an IP!"
  │                                     │
  │◄─── 2. OFFER ──────────────────────│  "I can offer you 192.168.1.10"
  │                                     │
  │──── 3. REQUEST (broadcast) ────────►│  "Yes, I'll take 192.168.1.10"
  │                                     │
  │◄─── 4. ACKNOWLEDGE ────────────────│  "Confirmed! It's yours for [lease time]"
  │                                     │
```

| Step | Name | Who sends | What it does |
|------|------|-----------|-------------|
| **D** | **Discover** | Client → broadcast | "I need an IP, is anyone there?" |
| **O** | **Offer** | Server → client | "Here's an available IP for you" |
| **R** | **Request** | Client → broadcast | "I accept that IP offer" |
| **A** | **Acknowledge** | Server → client | "Done — IP is yours for the lease duration" |

> 💡 **Lease time** — IP isn't permanent. After the lease expires, the device must renew it (or it gets a new IP).

### 🎯 Interview Q&A

**Q: What is DHCP and what is its main goal?**
> DHCP (Dynamic Host Configuration Protocol) automatically assigns IP addresses and network configuration to devices. Its main goal is to eliminate manual IP configuration — every device gets a unique IP automatically when it connects.

**Q: What protocol and ports does DHCP use?**
> DHCP uses **UDP** — port **67** on the server and port **68** on the client.

**Q: Explain the DORA process.**
> DORA is the 4-step DHCP handshake: **Discover** (client broadcasts asking for an IP), **Offer** (server proposes an IP), **Request** (client accepts the offer), **Acknowledge** (server confirms the lease). After ACK, the client has a valid IP.

**Q: What is a DHCP lease?**
> A lease is a time-limited assignment of an IP address. After the lease expires, the client must renew it, or the IP is returned to the pool for another device.

## 🔢 IP Classes

### What is an IP Address?
An IP address is a **32-bit** number (IPv4) written in **dotted-decimal** notation — 4 octets separated by dots (e.g. `192.168.1.1`).

### IPv4 Classes

| Class | Range | Default Subnet Mask | Use |
|-------|-------|--------------------|---------|
| **A** | `1.0.0.0` – `126.255.255.255` | `255.0.0.0` /8 | Large networks (ISPs, governments) |
| **B** | `128.0.0.0` – `191.255.255.255` | `255.255.0.0` /16 | Medium networks (universities) |
| **C** | `192.0.0.0` – `223.255.255.255` | `255.255.255.0` /24 | Small networks (home, small offices) |
| **D** | `224.0.0.0` – `239.255.255.255` | N/A | Multicast |
| **E** | `240.0.0.0` – `255.255.255.255` | N/A | Reserved / experimental |

> 💡 `127.x.x.x` is reserved for **loopback** (localhost) — `127.0.0.1` always refers to your own machine.

### Private IP Ranges (not routable on the internet)

| Class | Private Range |
|-------|---------------|
| A | `10.0.0.0` – `10.255.255.255` |
| B | `172.16.0.0` – `172.31.255.255` |
| C | `192.168.0.0` – `192.168.255.255` |

---

### 📍 Network Address & Broadcast Address

Every IP network has two **reserved** addresses that cannot be assigned to a device:

| Address | What it is | Example (192.168.1.0/24) |
|---------|-----------|------------------------|
| **Network Address** | First address — identifies the network itself | `192.168.1.0` |
| **Broadcast Address** | Last address — sends data to **all** devices on the network | `192.168.1.255` |
| **Usable Hosts** | Everything in between | `192.168.1.1` – `192.168.1.254` (254 hosts) |

```
Network:   192.168.1.0    ← not assignable
First host: 192.168.1.1
  ...        ...
Last host: 192.168.1.254
Broadcast: 192.168.1.255  ← not assignable
```

### 🎯 Interview Q&A

**Q: What is a network address?**
> The network address is the **first IP** in a subnet — it identifies the network itself and cannot be assigned to any host.

**Q: What is a broadcast address?**
> The broadcast address is the **last IP** in a subnet. A packet sent to it is delivered to **all devices** on that network.

**Q: What class is 192.168.1.1?**
> Class **C** — range `192.0.0.0` to `223.255.255.255`, default mask `/24` (`255.255.255.0`).

## 🏷️ Types of Addressing — Logical vs Physical

| | Logical Address (IP) | Physical Address (MAC) |
|-|----------------------|-----------------------|
| **What it is** | Software-assigned address | Hardware-burned-in address |
| **Layer** | Layer 3 — Network | Layer 2 — Data Link |
| **Format** | `192.168.1.1` (32-bit dotted decimal) | `AA:BB:CC:DD:EE:FF` (48-bit hex) |
| **Assigned by** | DHCP or manually | Manufacturer (burned into NIC) |
| **Changes?** | ✅ Can change (dynamic/static) | ❌ Permanent (can be spoofed though) |
| **Scope** | Routable across the internet | Local network only |
| **Protocol used** | IP | ARP maps IP → MAC |

> 💡 **ARP (Address Resolution Protocol)** — when a device knows the IP but needs the MAC, it broadcasts an ARP request: *"Who has 192.168.1.5?"* — the owner replies with its MAC address.

### 🎯 Interview Q&A

**Q: What is the difference between a logical and physical address?**
> A **logical address (IP)** is a software-assigned, routable address that can change. A **physical address (MAC)** is hardware-burned into the NIC, used only on the local network. IP works at Layer 3; MAC works at Layer 2.

**Q: What is ARP?**
> ARP (Address Resolution Protocol) maps an IP address to a MAC address on a local network. A device broadcasts *"Who has this IP?"* and the owner replies with its MAC.

**Q: Can a MAC address be changed?**
> MAC addresses are burned into the hardware but can be **spoofed** in software — this is called MAC spoofing and is a common attack technique.

## 🔀 NAT — Network Address Translation

### What is NAT?
NAT is a technique where a **router translates private (internal) IP addresses to a single public IP** before sending traffic to the internet — and reverses the translation for return traffic.

> 💡 NAT solves the **IPv4 exhaustion problem** — instead of every device needing a public IP, an entire network shares one.

### How NAT Works
```
[192.168.1.10] ──┐
[192.168.1.11] ──┤──► [Router / NAT] ──► Public IP: 203.0.113.5 ──► Internet
[192.168.1.12] ──┘
    (private)          (translates)         (one public IP)
```

### Types of NAT

| Type | Description |
|------|------------|
| **Static NAT** | One private IP ↔ one public IP (1:1 mapping) |
| **Dynamic NAT** | Pool of public IPs assigned dynamically to private IPs |
| **PAT / NAT Overload** | Many private IPs share **one public IP** using different port numbers — most common (home routers use this) |

> **PAT (Port Address Translation)** is the most common type — your home router maps `192.168.1.10:54321` → `203.0.113.5:54321` so it knows which internal device the reply belongs to.

### NAT Table (how the router tracks connections)

| Internal IP | Internal Port | Public IP | Public Port |
|-------------|---------------|-----------|-------------|
| 192.168.1.10 | 54321 | 203.0.113.5 | 54321 |
| 192.168.1.11 | 61000 | 203.0.113.5 | 61000 |

### 🎯 Interview Q&A

**Q: What is NAT and why is it used?**
> NAT (Network Address Translation) allows multiple devices with private IP addresses to share a single public IP address. It's used because IPv4 addresses are limited — NAT conserves public IPs and also adds a layer of obscurity (internal IPs aren't directly visible from the internet).

**Q: What is the difference between NAT and PAT?**
> NAT translates IP addresses. PAT (Port Address Translation), also called NAT Overload, goes further — it maps many private IP:port combinations to a **single public IP** using different port numbers to track each session.

**Q: Does NAT provide security?**
> NAT provides **obscurity** — internal IPs are hidden from the outside. But it's not a security mechanism by itself. A firewall is still needed for actual protection.

## 🌍 IPv4 vs IPv6

### What is an Octet?
> An **octet** is a group of **8 bits**. IPv4 addresses are made of **4 octets** (4 × 8 = 32 bits total).

```
192      .    168      .    1        .    1
11000000      10101000      00000001      00000001
[octet 1]    [octet 2]    [octet 3]    [octet 4]
  8 bits       8 bits       8 bits       8 bits
                    = 32 bits total
```

> Each octet ranges from **0 to 255** (2⁸ = 256 possible values).

---

### IPv4
- **32-bit** address → ~**4.3 billion** possible addresses
- Written as 4 dotted decimals: `192.168.1.1`
- Created in 1981 — nobody anticipated the internet would grow this large
- **Problem:** We are running out of IPv4 addresses

### IPv6
- **128-bit** address → **340 undecillion** possible addresses (340 × 10³⁶)
- Written as 8 groups of 4 hex digits separated by colons: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`
- Consecutive groups of zeros can be shortened with `::` → `2001:db8:85a3::8a2e:370:7334`

---

### Why is IPv6 Required?

| Reason | Explanation |
|--------|------------|
| **IPv4 exhaustion** | Only ~4.3 billion IPv4 addresses exist — nearly all allocated |
| **IoT explosion** | Billions of smart devices need unique IPs |
| **No more NAT workarounds** | Every IPv6 device can have a globally unique IP — no NAT needed |
| **Built-in security** | IPSec is **mandatory** in IPv6 (optional in IPv4) |
| **Better routing** | Simpler headers → faster router processing |
| **Auto-configuration** | Devices can self-assign IPs (SLAAC) without DHCP |

---

### IPv4 vs IPv6 — Side-by-Side

| Feature | IPv4 | IPv6 |
|---------|------|------|
| **Address size** | 32-bit | 128-bit |
| **Total addresses** | ~4.3 billion | 340 undecillion |
| **Notation** | Dotted decimal (`192.168.1.1`) | Hex with colons (`2001:db8::1`) |
| **Header size** | 20–60 bytes (variable) | Fixed 40 bytes (simpler) |
| **Security (IPSec)** | Optional | Mandatory |
| **NAT required?** | ✅ Yes (address shortage) | ❌ No (enough for all devices) |
| **Broadcast** | ✅ Has broadcast | ❌ No broadcast (uses multicast) |
| **DHCP** | Needed for auto-config | Optional (SLAAC available) |
| **Loopback** | `127.0.0.1` | `::1` |

---

### 🔁 Loopback Address

| Version | Loopback Address | Meaning |
|---------|-----------------|--------|
| IPv4 | `127.0.0.1` | "This machine" — entire `127.0.0.0/8` range is loopback |
| IPv6 | `::1` | Equivalent loopback in IPv6 |

> **Loopback** = a virtual address that routes traffic back to the **same device**.
> Used for: testing network software locally, running local servers, diagnosing network stack.

```
You ping 127.0.0.1
       ↓
 Does NOT leave your machine
       ↓
 Loops back to your own network stack
       ↓
 Reply comes from yourself
```

> 💡 If `ping 127.0.0.1` works → your TCP/IP stack is functioning correctly.

### 🎯 Interview Q&A

**Q: What is an octet?**
> An octet is 8 bits. IPv4 addresses consist of 4 octets (32 bits total), each ranging from 0 to 255.

**Q: Why was IPv6 introduced?**
> IPv4 only supports ~4.3 billion addresses and they are nearly exhausted. IPv6 uses 128-bit addresses, providing 340 undecillion addresses — enough for every device on earth and beyond. It also adds mandatory IPSec, simpler headers, and no need for NAT.

**Q: What is the loopback address?**
> `127.0.0.1` in IPv4 (or `::1` in IPv6). It routes traffic back to the same machine — used to test the local network stack without sending any traffic to the network.

**Q: What is the key difference between IPv4 and IPv6?**
> IPv4 is 32-bit (~4.3B addresses, dotted decimal, NAT required). IPv6 is 128-bit (340 undecillion addresses, hex colon notation, IPSec mandatory, no NAT needed, no broadcast).

## 🔪 Subnetting & CIDR

### What is Subnetting?
> **Subnetting** is the process of **dividing a large network into smaller, logical sub-networks (subnets)**.

Think of it like dividing a large office building into departments — each department (subnet) has its own IP range and doesn't directly talk to others without going through a router.

### Why Subnetting?

| Reason | Explanation |
|--------|------------|
| **Reduce network congestion** | Smaller broadcast domains = fewer devices receiving every broadcast |
| **Better security** | Isolate sensitive departments (HR, Finance) from general network |
| **Efficient IP use** | Allocate only the IPs a subnet actually needs |
| **Easier management** | Identify and isolate faults quickly |
| **Performance** | Less unnecessary traffic per subnet |

---

### Network Congestion & How Subnetting Helps

**What is network congestion?**
> When too many devices are on the same network, **broadcast traffic** explodes. Every ARP request, DHCP discover, and other broadcast goes to **every device** — wasting bandwidth and slowing everyone down.

```
Without subnetting (flat network):
[PC1][PC2][PC3]...[PC500] ← every broadcast hits ALL 500 devices
                            → congestion, slow network

With subnetting:
[Subnet A: PC1–PC100]  ← broadcasts stay within subnet A
[Subnet B: PC101–PC200] ← broadcasts stay within subnet B
[Subnet C: PC201–PC300] ← broadcasts stay within subnet C
                            → less congestion, faster network
```

> 💡 **Broadcast domain** = the group of devices that receive each other's broadcasts. Subnetting = shrinking broadcast domains.

---

### What is CIDR?
> **CIDR (Classless Inter-Domain Routing)** is a method of allocating IP addresses and routing that **replaces the old class-based system**.

Instead of being locked to Class A/B/C fixed sizes, CIDR lets you define **any prefix length** using `/` notation:

```
192.168.1.0/24
             ↑
        prefix length = 24 bits for network
        remaining 8 bits = host portion
```

### CIDR Cheat Sheet

| CIDR | Subnet Mask | Total IPs | Usable Hosts |
|------|------------|-----------|-------------|
| `/8` | `255.0.0.0` | 16,777,216 | 16,777,214 |
| `/16` | `255.255.0.0` | 65,536 | 65,534 |
| `/24` | `255.255.255.0` | 256 | 254 |
| `/25` | `255.255.255.128` | 128 | 126 |
| `/26` | `255.255.255.192` | 64 | 62 |
| `/27` | `255.255.255.224` | 32 | 30 |
| `/28` | `255.255.255.240` | 16 | 14 |
| `/30` | `255.255.255.252` | 4 | 2 |
| `/32` | `255.255.255.255` | 1 | 1 (single host) |

> **Usable hosts = Total IPs − 2** (subtract network address and broadcast address)

### 🧠 Remember
To find usable hosts for any subnet, remember the formula: **2^h - 2** (where `h` is the number of host bits).

### 💡 Common Mistake
Never assign the **Network Address** (first IP) or the **Broadcast Address** (last IP) to a device or router interface. They are strictly reserved.

---

### How to Read & Classify an IP

**Step 1 — Look at the first octet:**

| First Octet | Class | Type |
|-------------|-------|------|
| 1 – 126 | A | Public / Private (`10.x.x.x`) |
| 127 | — | Loopback (reserved) |
| 128 – 191 | B | Public / Private (`172.16–31.x.x`) |
| 192 – 223 | C | Public / Private (`192.168.x.x`) |
| 224 – 239 | D | Multicast |
| 240 – 255 | E | Reserved |

**Step 2 — Is it Private or Public?**

| Private Range | Class |
|--------------|-------|
| `10.0.0.0 – 10.255.255.255` | A |
| `172.16.0.0 – 172.31.255.255` | B |
| `192.168.0.0 – 192.168.255.255` | C |

> Everything else is **public** (routable on the internet)

**Quick classification example:**
```
IP: 172.20.5.1
→ First octet = 172 → Class B
→ Falls in 172.16.0.0 – 172.31.255.255 → Private
```

---

### Subnetting Example

```
Given: 192.168.1.0/26

Subnet mask:     255.255.255.192
Total IPs:       64
Usable hosts:    62
Network address: 192.168.1.0    ← first
Broadcast:       192.168.1.63   ← last
First host:      192.168.1.1
Last host:       192.168.1.62
```

### 🎯 Interview Q&A

**Q: What is subnetting and why is it used?**
> Subnetting divides a large network into smaller sub-networks. It reduces broadcast traffic and network congestion, improves security by isolating segments, and makes IP allocation more efficient.

**Q: What is CIDR?**
> CIDR (Classless Inter-Domain Routing) replaces the old fixed class system. It uses a `/prefix` notation (e.g. `/24`) to define how many bits belong to the network portion, allowing flexible-sized subnets instead of being locked to class sizes.

**Q: How many usable hosts are in a /24 network?**
> 256 total IPs − 2 (network + broadcast) = **254 usable hosts**.

**Q: What is a broadcast domain and how does subnetting help?**
> A broadcast domain is a group of devices that all receive each other's broadcast packets. In a large flat network, every broadcast hits every device — causing congestion. Subnetting shrinks broadcast domains, so broadcasts only reach devices in the same subnet.

**Q: How do you classify the IP `10.0.0.1`?**
> First octet is 10 → **Class A**. It falls in the `10.0.0.0/8` range → **Private IP**.

**Q: What is the difference between a subnet mask and CIDR notation?**
> Both represent the same thing differently. `/24` (CIDR) = `255.255.255.0` (subnet mask). CIDR is shorthand — it counts how many bits are 1s in the mask.

## 🔐 SSH — Secure Shell

### What is SSH?
> **SSH (Secure Shell)** is a **cryptographic network protocol** used to securely access and manage remote machines over an unsecured network. It runs on **TCP port 22**.

> SSH replaced older insecure protocols like **Telnet** (port 23) and **rsh** — which sent everything including passwords in **plain text**.

| | Telnet | SSH |
|-|--------|-----|
| **Port** | 23 | 22 |
| **Encryption** | ❌ None | ✅ Full encryption |
| **Password** | Sent in plain text | Encrypted |
| **Use today** | ❌ Unsafe, avoid | ✅ Standard for remote access |

---

### How SSH Works — Step by Step

```
Client                          Server (port 22)
  │                                  │
  │─── 1. TCP Connection ─────────►│
  │                                  │
  │◄── 2. Server sends public key ──│  (client verifies it's the right server)
  │                                  │
  │↔── 3. Key Exchange (ECDH/DH) ──│  (both sides agree on a shared secret)
  │                                  │
  │↔── 4. Symmetric Encryption ON ──│  (all traffic now encrypted)
  │                                  │
  │─── 5. Authentication ─────────►│  (password OR SSH key pair)
  │                                  │
  │↔── 6. Secure Shell Session ─────│  (now you can run commands remotely)
```

### The 3 Layers of SSH

| Layer | Name | What it does |
|-------|------|--------------|
| 1 | **Transport Layer** | Handles encryption, integrity, server authentication |
| 2 | **Authentication Layer** | Verifies who the client is (password / key) |
| 3 | **Connection Layer** | Manages multiple channels (shell, file transfer, tunnels) |

---

### SSH Authentication Methods

#### Method 1 — Password Authentication
```
Client ──► "username + password" ──► Server checks credentials
```
- Simple but weaker — brute-force risk
- Password travels **encrypted** (unlike Telnet)

#### Method 2 — SSH Key Pair Authentication (recommended)
```
1. Generate a key pair:
   ├─ Private key  ← stays on YOUR machine (never share)
   └─ Public key   ← placed on the remote server

2. When connecting:
   Client proves it holds the private key
   Server checks it matches the stored public key
   → No password needed — much more secure
```

> 🔑 **Private key** = your identity proof. **Never share it.**
> � udd13 **Public key** = the lock on the server. Anyone can have it.

### 💻 How to Use SSH — Commands

#### Basic Connection
```bash
# Connect to a remote server
ssh username@hostname_or_ip

# Example
ssh john@192.168.1.10
ssh john@example.com

# Connect on a non-default port
ssh -p 2222 john@192.168.1.10
```

#### SSH Key Pair Setup
```bash
# Step 1: Generate a key pair (on your local machine)
ssh-keygen -t rsa -b 4096
# Creates:
#   ~/.ssh/id_rsa       ← private key
#   ~/.ssh/id_rsa.pub   ← public key

# Step 2: Copy public key to the server
ssh-copy-id username@remote_ip
# OR manually append to ~/.ssh/authorized_keys on server

# Step 3: Connect without password
ssh username@remote_ip
```

#### Useful SSH Options
```bash
# Connect with a specific private key file
ssh -i ~/.ssh/my_key.pem username@ip

# Run a single command remotely (no interactive shell)
ssh username@ip "ls -la /var/www"

# Verbose mode (debug connection issues)
ssh -v username@ip

# Enable X11 forwarding (run GUI apps remotely)
ssh -X username@ip
```

#### File Transfer over SSH
```bash
# SCP — copy files over SSH
scp file.txt username@ip:/remote/path/       # local → remote
scp username@ip:/remote/file.txt ./          # remote → local
scp -r folder/ username@ip:/remote/path/     # copy a directory (-r)

# SFTP — interactive file transfer
sftp username@ip
  > ls          # list remote files
  > get file    # download
  > put file    # upload
  > exit
```

#### SSH Tunneling / Port Forwarding
```bash
# Local port forwarding — access a remote service locally
ssh -L 8080:localhost:80 username@remote_ip
# Now visiting localhost:8080 on your machine → hits remote port 80

# Dynamic SOCKS proxy (like a VPN)
ssh -D 9090 username@remote_ip
```

| **Secure file transfer (SCP/SFTP)** | Copy files securely between machines |
| **Git over SSH** | Push/pull code to GitHub/GitLab securely |

### SSH Security Best Practices

| Practice | Why |
|----------|-----|
| **Use key-pair auth, disable password auth** | Eliminates brute-force attacks |
| **Change default port 22** | Reduces automated scan noise |
| **Disable root login** (`PermitRootLogin no`) | Attackers can't directly target root |
| **Use `fail2ban`** | Auto-bans IPs after failed login attempts |
| **Keep SSH updated** | Patch known vulnerabilities |
| **Use strong key types** | Prefer `ed25519` over old RSA 1024-bit |

### 🎯 Interview Q&A

**Q: What is SSH and what port does it run on?**
> SSH (Secure Shell) is a cryptographic protocol for securely accessing and managing remote systems over an unsecured network. It runs on **TCP port 22**.

**Q: How does SSH work?**
> SSH establishes a TCP connection, the server presents its public key (client verifies it), both sides perform a key exchange to derive a shared symmetric key, all traffic is then encrypted, and finally the client authenticates (password or key pair). After that, a secure shell session begins.

**Q: What is the difference between SSH and Telnet?**
> Telnet (port 23) sends everything — including passwords — in plain text. SSH (port 22) encrypts all traffic. Telnet is unsafe and should never be used; SSH is the modern standard.

**Q: What is SSH key-pair authentication?**
> A key pair consists of a **private key** (kept secret on the client) and a **public key** (placed on the server). When connecting, the client proves ownership of the private key. The server verifies it matches the stored public key — no password needed. Much more secure than passwords.

**Q: What is SCP?**
> SCP (Secure Copy Protocol) uses SSH to securely transfer files between machines. Example: `scp file.txt user@ip:/path/`.

**Q: What is SSH port forwarding?**
> SSH port forwarding (tunneling) lets you securely route traffic through an SSH connection. For example, `ssh -L 8080:localhost:80 user@server` lets you access a remote web server on port 80 through your local port 8080 — all encrypted.

**Q: How do you harden an SSH server?**
> Disable password authentication (use keys only), disable root login, change the default port from 22, use `fail2ban` to block brute-force, and use modern key types like `ed25519`.

### What is Enumeration?
> **Enumeration** is the process of actively extracting detailed information from a target — usernames, shares, services, versions, banners — after initial discovery. It's **Phase 1 (Recon/active)** of the Kill Chain, deeper than a port scan.

```
Port Scan (nmap) → find open ports
       ↓
Enumeration      → extract details FROM those open ports
       ↓
Exploitation     → use those details to attack
```

### 🎯 Interview Q&A

**Q: What is enumeration in cybersecurity?**
> Enumeration is the active process of extracting detailed information from discovered services — such as usernames, shares, software versions, and configurations. It goes deeper than a port scan and feeds directly into exploitation.

**Q: What tool would you use to enumerate SMB shares?**
> `enum4linux -a target` for a full dump, `smbclient -L //target -N` to list shares, and `smbmap -H target` to check share permissions. `crackmapexec` is also widely used in modern pentests.

**Q: How do you check for anonymous FTP login?**
> Use `nmap --script ftp-anon -p 21 target` or connect manually with `ftp target` and try `anonymous` as the username with a blank password.

**Q: What is a null session in SMB?**
> A null session is an unauthenticated connection to an SMB service. On misconfigured systems it can expose user lists, group memberships, share names, and OS information — all without credentials.

**Q: What does enum4linux do?**
> enum4linux is a Linux tool for enumerating information from Windows and Samba systems via SMB. It retrieves OS info, users, groups, shares, and password policies — essentially a full SMB dump.

**Q: What is the difference between a port scan and enumeration?**
> A port scan (e.g. nmap) tells you which ports are open and what service is running. Enumeration goes deeper — it extracts usernames, versions, configs, and shares from those services to find attack vectors.

| **TCP** | SYN Flood (DoS) | Attacker sends many SYN packets, ignoring SYN/ACKs, exhausting server resources. |
| **TCP** | Session Hijacking | Intercepting a session and predicting sequence numbers to take over. |
| **TCP** | Man-in-the-Middle | Intercepting unencrypted traffic (e.g., HTTP, Telnet) to read or modify data. |
| **DNS** | Cache Poisoning / Spoofing | Injecting fake DNS records into a resolver to redirect users to malicious IPs. |
| **DNS** | Zone Transfer (`AXFR`) | Dumping all DNS records from a misconfigured authoritative server. |
| **DNS** | Amplification DDoS | Spoofing victim's IP and sending small queries to DNS servers; servers flood victim with large responses. |
| **MAC/ARP** | MAC Spoofing | Changing the software MAC address to impersonate another device or bypass filters. |
| **FTP** | Anonymous Login | Misconfiguration allowing anyone to log in with user `anonymous` and no password. |
| **SMB** | Null Session | Unauthenticated SMB connection that can leak users, groups, and shares. |
| **SMTP** | User Enumeration | Using `VRFY` or `EXPN` commands to verify if an email address exists on the server. |
| **SSH vs Telnet**| Plaintext Sniffing | Telnet sends passwords in cleartext (easily sniffed). SSH encrypts them. |
| **Brute-Forcing** | Credential Stuffing | Using tools like Hydra/Medusa with wordlists to guess passwords for SSH, FTP, SMB. |

## 📝 Summary / TL;DR

The **Cyber Kill Chain** has 7 phases — recon first and best disruption point. **Passive recon** = no trace; **active recon** = logged; **OSINT** = public data only. **Ports**: 22=SSH, 23=Telnet, 80=HTTP, 443=HTTPS, 53=DNS, 67/68=DHCP. **TCP** = reliable, connection-oriented, 3-way handshake, needs TLS for security; **UDP** = connectionless, fast, no guarantee. **DTP** = FTP data channel (port 20). **DNS** = phonebook; records: A (IPv4), AAAA (IPv6), CNAME (alias); Google DNS = 8.8.8.8. **DHCP** auto-assigns via **DORA** (Discover→Offer→Request→Ack) over UDP 67/68. **IP**: 32-bit, 4 octets (0–255); Classes A/B/C; private: `10.x`, `172.16–31.x`, `192.168.x`; loopback = `127.0.0.1`. **IPv6** = 128-bit, mandatory IPSec, no NAT/broadcast, loopback = `::1` — needed due to IPv4 exhaustion. **CIDR** = flexible prefix notation (`/24`=254 hosts); **Subnetting** = splits networks to cut broadcast congestion + improve security. **Logical** = IP (L3); **Physical** = MAC (L2); ARP maps IP→MAC. **NAT/PAT** = many private IPs share one public IP via ports. **SSH** (port 22) = encrypted remote shell; replaces Telnet; uses asymmetric key exchange then symmetric encryption; auth via password or key pair; used for remote management, SCP/SFTP file transfer, tunneling, and Git.
