# Burp Suite & The Intercepting Proxy

`[ BURP ]` `[ SUITE ]` `[ INTERCEPTING ]` `[ PROXY ]`

> **Course:** Cybersecurity
> **Date:** 2026-08-14 | **Session:** 04

---


## 1. What is it?
**Burp Suite** (developed by PortSwigger) is the industry-standard software for web application security testing. 

At its core, it acts as an **Intercepting Proxy**. In simple terms, it is a tool that sits between your web browser and the internet, allowing you to pause, inspect, and modify web traffic before it reaches the server or returns to your browser.

## 2. Why does it happen?
*Why does this tool exist?*
Web browsers are designed to communicate directly with servers and hide the underlying HTTP requests and responses from the user to provide a seamless experience. However, security professionals need to see and manipulate this raw data to find vulnerabilities like hidden form manipulation, SQL injection, and parameter tampering. Burp Suite exists to give testers full control over this traffic.

## 3. How does it work?
Normally, traffic flows like this:
```text
Browser ◄────────(HTTPS)────────► Web Server
```

When you set up Burp Suite, you configure your browser to route all traffic through a local port (usually `127.0.0.1:8080`). Burp acts as a local server intercepting the communication:
```text
Browser ◄──► Burp Suite Proxy (127.0.0.1:8080) ◄──► Web Server
```

Because Burp Suite intercepts the traffic *before* it reaches the server, it can pause the request. For HTTPS (encrypted) traffic, Burp acts as a **Man-in-the-Middle (MitM)**. You must install Burp's Certificate Authority (CA) certificate in your browser so the browser trusts Burp to decrypt and re-encrypt the HTTPS traffic.

## 4. Where is it used / found?
Burp Suite is used globally by penetration testers, bug bounty hunters, and security analysts when testing web applications, mobile app APIs, and any client-server communication that relies on HTTP/HTTPS.

It comes in multiple editions: **Community Edition** (free, used by students/beginners, rate-limited automated tools), **Professional Edition** (paid, uncapped tools, used by pro hackers), and **Enterprise Edition** (for automated continuous CI/CD scanning).

## 5. How do I identify it?
As a tester, you know Burp is actively intercepting if:
- Your browser traffic is routing through `127.0.0.1:8080` (often managed via the **FoxyProxy** extension).
- Web pages appear to "hang" or infinitely load while Burp holds the request in the **Proxy -> Intercept** tab.
- If the CA certificate is missing, the browser will display a `SEC_ERROR_UNKNOWN_ISSUER` warning for HTTPS sites instead of loading them.

## 6. Hands-on / Lab Methodology

```text
🧪 HANDS-ON
━━━━━━━━━━━━━━━━━━━━
```
If you want to practice intercepting requests in an authorized lab:
- **What to observe first:** Ensure Burp Suite is running, and FoxyProxy is set to route browser traffic to Burp.
- **Attack surface:** Any web application that accepts user input (login forms, URL parameters, cookies).
- **Initial hypothesis:** We can manipulate the request parameters (e.g., change an ID) before the server processes them.
- **What to test:** Capturing a login request or an item purchase request, and modifying the parameters.
- **How to test it safely (authorized lab):** Navigate to the target application, ensure **Intercept is on** in the Burp Proxy tab, submit the web form, and observe the captured request in Burp.
- **Expected result:** The request is paused in Burp, and the browser indicates it's waiting for a response.
- **How to interpret the result:** We can now edit the raw HTTP text. Clicking **Forward** sends our modified request to the server, while **Drop** kills the request completely. We can also right-click and send it to **Repeater** to test variations.

## 7. Failed Attempts & Why
> ⚠️ **FAILED ATTEMPTS / LESSONS LEARNED**
> 
> - **What was tried:** Attempting to intercept HTTPS traffic immediately after setting up the proxy, without installing the PortSwigger CA certificate.
- **Why it failed:** The browser detected a Man-in-the-Middle attempting to present an untrusted certificate and blocked the connection with a red warning.
- **What that tells us:** Modern browsers protect users from unknown proxies intercepting encrypted traffic.
- **What to try next:** Download `cacert.der` from `http://burp` (while proxying through Burp) and import it into the browser's trusted Authorities, making sure to check the **"Trust this CA to identify websites"** box.

Another common failure: 
- **What was tried:** Browsing the web with FoxyProxy set to "Burp Suite".
- **Why it failed:** Received a "Proxy server refusing connections" error. 
- **What that tells us:** Burp Suite was closed, so the browser was sending traffic to a dead port. 
- **What to try next:** Start Burp Suite, or switch FoxyProxy back to "Disable".


## 8. Example
Imagine a shopping site where the price of an item is submitted as a hidden HTML form field: 
`<input type="hidden" name="price" value="100.00">`

Normally, a user just clicks "Buy". Using Burp Suite, you intercept the checkout request before it leaves your machine and modify the `price` parameter from `100.00` to `1.00`. If the server lacks backend validation and blindly trusts the client input, you successfully purchase the item for $1.

## 9. Impact
By intercepting and modifying traffic, an attacker can exploit critical vulnerabilities like SQL Injection, Cross-Site Scripting (XSS), Insecure Direct Object References (IDOR), and broken access control. The impact ranges from unauthorized data access to full system compromise.

## 10. Detection
A SOC analyst or defender can detect malicious payloads generated via Burp Suite (especially automated tools like **Intruder**) by monitoring Web Application Firewalls (WAF) or server logs for:
- High volumes of requests from a single IP (brute-forcing/fuzzing).
- Unusual or malformed HTTP headers.
- Payloads containing common injection strings (e.g., `admin' OR 1=1--`).
- Default Burp Suite user-agent strings (if the tester forgets to change them in their tools).

## 11. Prevention / Remediation
To prevent vulnerabilities exploited via intercepting proxies, developers must:
- Implement robust **server-side validation** for all input. Never trust client-side controls (hidden fields, JavaScript validation), as Burp can bypass them effortlessly.
- Use parameterized queries to prevent SQL injection.
- Implement rate-limiting and account lockout mechanisms to thwart automated brute-forcing by tools like Intruder.

## 12. Related Concepts
- **HTTP/HTTPS Protocols:** Understanding request methods (GET, POST), headers, and status codes is fundamental before using Burp.
- **TLS/SSL Encryption:** Explains why the CA certificate is strictly necessary to intercept HTTPS traffic.
- **Man-in-the-Middle (MitM):** Burp Suite functions identically to a MitM attack, but locally and deliberately for testing purposes.

## 13. Important Commands / Syntax
- `http://burp` : The local URL to download the PortSwigger CA certificate (only works when Burp is running and your browser is proxying through it).
- `Ctrl+R` / `Cmd+R` : Send the currently selected request to the **Repeater** tab.
- `Ctrl+I` / `Cmd+I` : Send the currently selected request to the **Intruder** tab.

## 14. Interview Questions
**Q: What is the primary function of Burp Suite?**
> It acts as an Intercepting Proxy, allowing testers to capture, inspect, and modify HTTP/HTTPS traffic flowing between the browser and the web server.

**Q: Why do you need to install the PortSwigger CA Certificate in your browser?**
> Because Burp Suite acts as a Man-in-the-Middle. To intercept encrypted HTTPS traffic, the browser must explicitly trust Burp's CA to decrypt and re-encrypt the traffic, otherwise the browser throws a security warning and blocks the connection.

**Q: What is the difference between the Proxy, Repeater, and Intruder tabs?**
> The **Proxy** tab intercepts live traffic in real-time. The **Repeater** tab takes a single captured request and lets you manually modify and re-send it multiple times. **Intruder** automates the process of sending high volumes of modified requests for fuzzing or brute-forcing.

**Q: How do you fix a "Proxy server refusing connections" error in your browser?**
> This happens when your browser proxy extension (like FoxyProxy) is routing traffic to port 8080, but Burp Suite is not currently running. You fix it by either starting Burp Suite or disabling the proxy in the browser.

## 16. Key Takeaways
> 💡 **KEY TAKEAWAYS**
> 
> - Burp Suite is the foundational tool for web application security testing.
> - It operates as a local **Intercepting Proxy** (typically on `127.0.0.1:8080`).
> - You must configure a browser extension like **FoxyProxy** to easily toggle traffic routing to Burp.
> - You must install the **PortSwigger CA certificate** to intercept HTTPS traffic without browser errors.
> - **Repeater** is for manual, iterative testing of a single request.
> - **Intruder** is for automated fuzzing/brute-forcing (but is rate-limited in the free Community Edition).
> - **Extensions** (from the BApp Store) add functionality, like Logger++ or Autorize.
> - Never trust client-side validation, because intercepting proxies can easily bypass it.
>

Burp Suite is an Intercepting Proxy that sits between your browser and the web server. By configuring your browser proxy (via FoxyProxy) to route traffic to `127.0.0.1:8080` and installing Burp's CA certificate, you can intercept, pause, and modify both HTTP and HTTPS requests. You use the **Proxy** tab to catch live traffic, send interesting requests to the **Repeater** tab to manually test for vulnerabilities by tweaking inputs, and use **Intruder** for automated brute-forcing. The existence of tools like Burp proves that servers must validate all input on the backend, because attackers can manipulate anything in transit.
