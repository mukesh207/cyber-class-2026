# Cybersecurity Study Notes: Non-Repudiation in the SOC

## The Big Picture: How It All Works Together
In cybersecurity, we often focus on the **CIA Triad** (Confidentiality, Integrity, Availability). However, when you step into a **Security Operations Center (SOC)**, another concept becomes absolutely critical for incident response, forensics, and compliance: **Non-repudiation**.

**Non-repudiation** is the assurance that a party cannot deny the validity of an action they performed or a message they sent. In the context of a SOC, it means: *If a user executes a malicious command, deletes a file, or approves a fraudulent transaction, they cannot later claim, "It wasn't me!" or "The system made an error."* 

Without non-repudiation, every security investigation hits a dead end where the suspect simply denies involvement, and the SOC lacks the undeniable proof to counteract that claim.

## Why Non-Repudiation is Critical for a SOC

1. **Undeniable Accountability:** A SOC needs to attribute actions to specific individuals (or compromised service accounts) with 100% certainty. 
2. **Forensic Integrity (Chain of Custody):** When collecting evidence for legal prosecution or HR disciplinary action, the evidence must be mathematically and cryptographically proven to be authentic and untampered.
3. **Insider Threat Detection:** Insiders often try to cover their tracks. Non-repudiation mechanisms (like sending logs to an immutable off-site server) prevent malicious admins from erasing proof of their actions.

---

## Theory vs. Practice: Core Mechanisms

To achieve non-repudiation, a SOC relies on a combination of technologies. It is not a single tool, but an overlapping ecosystem of security controls.

| Concept / Tool | What it does | How it enforces Non-Repudiation |
| :--- | :--- | :--- |
| **Multi-Factor Authentication (MFA)** | Requires something you *know* (password) + something you *have* (token) or *are* (biometrics). | If an action occurs under an account, MFA makes it incredibly difficult for the user to claim they were simply "hacked" via a guessed password. |
| **Digital Signatures (PKI)** | Uses asymmetric cryptography (Private/Public key pairs) to sign data. | Only the holder of the **Private Key** could have generated the signature. If the signature matches the public key, the sender cannot deny sending it. |
| **Cryptographic Hashing (SHA-256)** | Generates a unique, fixed-size mathematical representation of a file or log. | If a SOC analyst images a hard drive, they hash it immediately. This proves the evidence was not altered during the investigation. |
| **Immutable Logging (WORM)** | Write-Once, Read-Many storage for SIEM logs. | Even a domain admin cannot delete or alter the logs once they are written. The historical record is undeniable. |

## Real-Time Technical Scenario: The Rogue Admin

**Scenario:** A disgruntled network administrator (`Admin_Bob`) decides to sabotage the company by deleting the core firewall rules right before quitting. He attempts to cover his tracks by logging into the firewall, executing the deletion, and then deleting the local firewall logs.

**How Non-Repudiation Catches Him:**

```text
+----------------+      (1) Logs in via SSH      +-----------------------+
|                |      using MFA Token &        |                       |
|   Admin_Bob    | ----------------------------> |  Core Edge Firewall   |
| (Workstation)  |      Personal Admin Creds     |   (Target System)     |
|                |                               |                       |
+----------------+                               +-----------------------+
                                                            |
                                                            | (2) Bob deletes rules.
                                                            | Firewall generates Syslog.
                                                            v
+----------------+      (4) SOC Analyst          +-----------------------+
|                |      reviews immutable        |                       |
|   SOC SIEM     | <---------------------------- |  Central Log Forwarder|
|  (WORM Drive)  |      logs. Bob cannot         |  (Hashes logs as they |
|                |      deny the action!         |   are generated)      |
+----------------+                               +-----------------------+
```

**The Investigation Workflow:**
1. **The Alert:** The SOC receives a critical alert: *Firewall traffic suddenly dropping, rules flushed.*
2. **The Investigation:** The SOC analyst pulls logs from the **SIEM** (Security Information and Event Management system). 
3. **The Proof (Non-repudiation):** 
   - The SIEM shows the action was taken by `Admin_Bob`. 
   - Bob says, "Someone stole my password!" 
   - The SOC checks the logs and sees the session was authenticated using Bob's hardware MFA token (YubiKey) which requires physical touch.
   - Bob says, "The logs are fake!"
   - The SOC proves the logs are authentic because they are stored on a **WORM** (Write-Once, Read-Many) drive and secured with a **Digital Signature** generated by the firewall at the exact moment of the event.

**Conclusion:** Bob is undeniably tied to the action. This evidence holds up in court.

# Cybersecurity Study Notes: SOC Tools & Technology Ecosystem

## The Big Picture: The SOC Hospital
Think of the SOC as an emergency room. You have a lot of different diagnostic tools—an X-ray, an MRI, a blood tester. None of these tools cure the patient on their own. Instead, they all send their results to the doctor's clipboard so the doctor can make an informed decision. 

In a SOC, the **SIEM** is the doctor's clipboard. The **EDR**, **NDR**, and **Vulnerability Scanners** are the diagnostic tools sending it telemetry. And the **SOAR** is the automated medicine dispenser that kicks in when a known sickness is detected.

## Core SOC Technologies

Instead of memorizing acronyms, let's group these tools by *where* they sit and *what* they do.

| Technology Category | Tool Acronym | What it Actually Does | Industry Examples |
| :--- | :--- | :--- | :--- |
| **The Brain (Central Hub)** | **SIEM** (Security Information & Event Management) | Ingests logs from *every* device in the network. Correlates events to detect complex attacks. | Splunk, IBM QRadar, Microsoft Sentinel |
| **The Automation Engine** | **SOAR** (Security Orchestration, Automation & Response) | Plugs into the SIEM. If the SIEM sees a bad IP, SOAR runs a script to tell the firewall to block it automatically. | Cortex XSOAR, Splunk SOAR |
| **The Endpoint Watchdog** | **EDR** (Endpoint Detection & Response) | An agent installed on laptops/servers. It monitors memory, running processes, and file changes. | CrowdStrike, SentinelOne |
| **The Network Watchdog** | **NDR** (Network Detection & Response) | A sensor on the network switch. It analyzes packets and traffic flow for anomalies. | Darktrace, ExtraHop |
| **The Perimeter Guards** | **IDS/IPS** (Intrusion Detection/Prevention System) | Sits at the edge. IDS *alerts* when it sees bad traffic. IPS *blocks* bad traffic in real-time. | Snort, Suricata, Cisco Firepower |
| **The Omniscient Eye** | **XDR** (Extended Detection & Response) | The evolution of EDR. It combines endpoint, network, and cloud data into one agent/platform. | Palo Alto Cortex XDR |
| **The Profiler** | **UEBA** (User & Entity Behavior Analytics) | Uses machine learning to establish a baseline of "normal" user behavior and flags weird deviations. | Exabeam, Securonix |
| **The Informant** | **Threat Intelligence** | Feeds of known bad IPs, domains, and file hashes that enrich the SIEM's detection capabilities. | Recorded Future, VirusTotal |
| **The Proactive Inspector** | **Vulnerability Scanner** | Scans the network for missing patches or misconfigurations *before* an attacker can exploit them. | Nessus, OpenVAS, Qualys |

## Real-Time Technical Scenario: The Phishing Payload

**The Attack:** An employee receives a phishing email and downloads a malicious Word document. 
**The SOC Response (Step-by-Step):**

1. **UEBA** flags that `User_Alice` is opening a macro-enabled document, which she rarely does.
2. The **EDR** agent on Alice's laptop sees Microsoft Word spawn a suspicious PowerShell process. It alerts the **SIEM**.
3. The **NDR** detects the PowerShell process trying to make a network connection to an external Russian IP address. It alerts the **SIEM**.
4. The **SIEM** correlates the EDR alert and the NDR alert. It queries the **Threat Intelligence** feed, which confirms the Russian IP belongs to a ransomware gang.
5. The **SIEM** triggers a High Severity Alert and passes it to **SOAR**.
6. **SOAR** executes a playbook: It uses an API to tell the **EDR** to isolate Alice's laptop from the network, and tells the **IPS** to block the Russian IP for the entire company.

*All of this happens in milliseconds, potentially stopping a ransomware infection before it encrypts the drive.*

**Focus:** Introduction to Blue Teaming, Threat Detection, and Incident Response.

**Key Technical Takeaways:**
* **Defensive Security** relies on two pillars: **Prevention** (Patching, Firewalls, User Awareness) and **Detection/Response** (SOC monitoring, investigating anomalies).
* **The Defensive Ecosystem:**
  * **Threat Intelligence:** Provides the IOCs (Indicators of Compromise) and attacker TTPs to the team.
  * **SOC:** Uses those IOCs to monitor network logs and alerts actively.
  * **DFIR:** Investigates breaches post-incident and contains the threat.
  * **Malware Analysis:** Dissects malicious executables in a sandbox.
* **FakeBank Simulation Observation:** Successfully correlated an external IP causing a traffic spike on Port 80 with a Threat Intel feed (known botnet). Responded by configuring an **IPS (Intrusion Prevention System)** to instantly drop packets from that malicious IP, protecting the server.
