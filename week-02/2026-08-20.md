# Path Traversal and OS Command Injection

> **Course:** Cybersecurity
> **Date:** 2026-08-20 | **Session:** 06

---

## 1. What is it?
- **Path Traversal (Directory Traversal):** Simply put, it's a flaw that lets an outsider read files they aren't supposed to, like server configuration files or passwords. Technically, it is a web security vulnerability that allows an attacker to read arbitrary files on the server that is running an application.
- **OS Command Injection:** Simply put, it's a flaw that lets an outsider run terminal commands on the server. Technically, it's a web security vulnerability that allows an attacker to execute arbitrary operating system commands on the server that is running an application.

## 2. Why does it happen?
These vulnerabilities happen due to a lack of input validation and sanitization.
- **Path Traversal** happens when an application uses user-supplied input to construct a file path for reading or writing data, without adequately ensuring the user hasn't escaped the intended directory.
- **OS Command Injection** happens when an application passes unsafe user-supplied data (forms, cookies, HTTP headers, etc.) to a system shell. The system shell processes the attacker's payload as a command.

## 3. How does it work?

### Path Traversal Flow
```text
[ Attacker ] ---> Requests: ?filename=../../../etc/passwd ---> [ Web Server ]
                                                                     |
                                                                     v
                                                            [ Local File System ]
                                                            Reads /etc/passwd instead
                                                            of intended directory.
```

### OS Command Injection Flow
```text
[ Attacker ] ---> Sends: storeId=1|whoami ---> [ Web Server / App ]
                                                      |
                                                      v
                                              [ System Shell ]
                                         Executes: stock_check.sh 1 | whoami
```

## 4. Where is it used / found?
- **Path Traversal:** Found in web application features that interact with the file system, like loading images, downloading documents, or templating systems loading files.
- **OS Command Injection:** Found in applications that wrap system tools or scripts, such as a "ping" utility on a router interface, server health checks, or video/image processing using backend OS tools.

## 5. How do I identify it?
- **Path Traversal:** Look for parameters in requests that suggest file interactions, such as `?filename=`, `?file=`, `?doc=`, `?folder=`. 
- **OS Command Injection:** Look for parameters that might be passed to a script. Look for changes in response times (time-based injection) or unexpected output appended to normal responses when adding command separators (`|`, `;`, `&&`).

## 6. Hands-on / Lab Methodology
*Assuming an authorized lab environment (e.g., PortSwigger).*

- **What to observe first:** Note the normal behavior of the application. Find features that fetch files (e.g., `?filename=53.jpg`) or seem to perform system-level tasks (e.g., "Check stock").
- **Attack surface:** URL parameters, form fields, and occasionally HTTP headers (like User-Agent or Referer).
- **Initial hypothesis:** The application might not be validating or sanitizing the input before passing it to the file system API or OS shell.
- **What to test:** 
  - Path Traversal: Test basic payloads `../../../etc/passwd`.
  - Command Injection: Test basic separators `| whoami` or `; whoami`.
- **How to test it safely (authorized lab):** Use **Burp Suite Repeater** to modify specific requests without the browser interface getting in the way.
- **Expected result:** 
  - Path Traversal: The response body contains the contents of `/etc/passwd`.
  - Command Injection: The response body contains the output of the `whoami` command.
- **How to interpret the result:** If the attack succeeds, it proves the backend is unsafely processing the input. If it fails, the application might be filtering or validating the input (requiring bypass techniques).

## 7. Failed Attempts & Why
- **What was tried:** Basic path traversal `../../../etc/passwd`.
- **Why it failed:** The server blocked or stripped `../` sequences.
- **What that tells us:** A filter or WAF is active.
- **What to try next:** 
  - Try absolute paths: `/etc/passwd`.
  - Try nested traversal (if stripped non-recursively): `....//....//etc/passwd`.
  - Try URL encoding: `%252e%252e%252f` (double-encoding).
  - Try appending a null byte if extensions are checked: `../../../etc/passwd%00.png`.

## 8. Example
- **Path Traversal:** The application fetches images using `<img src="/loadImage?filename=218.png">`. The attacker modifies the request to `/loadImage?filename=../../../etc/passwd`. The server reads the password file instead of an image.
- **OS Command Injection:** The application checks stock by running a backend script with a provided ID: `check_stock.sh 1`. The attacker provides `1|whoami`. The shell executes `check_stock.sh 1 | whoami`, and the web page displays the username the server is running as.

## 9. Impact
- **Path Traversal:** Attackers can read sensitive files (passwords, source code, config files, SSH keys). This can lead to full server compromise.
- **OS Command Injection:** Attackers can run arbitrary commands. This is a critical vulnerability leading directly to Remote Code Execution (RCE) and full server takeover.

## 10. Detection
- **SOC / WAF:** Look for common attack strings like `../`, `..%2f`, `%00`, `/etc/passwd`, `cmd.exe`, or shell metacharacters in web request logs.
- **Endpoint Detection & Response (EDR):** Detect web server processes (e.g., `nginx`, `apache`, `tomcat`) unexpectedly spawning shells (`sh`, `bash`, `cmd.exe`) or executing unusual commands (`whoami`, `netcat`).

## 11. Prevention / Remediation
- **Path Traversal:** 
  - Avoid passing user-supplied input to filesystem APIs if possible. 
  - If unavoidable, validate input against a strict allowlist of permitted values.
  - Normalize the requested path and verify it starts with the expected base directory.
- **OS Command Injection:**
  - Never call out to OS commands from application-layer code if there are built-in library alternatives.
  - If unavoidable, perform strong input validation (allowlists).
  - Do not use shell interpreters (like `bash -c`); instead, use execution APIs that pass arguments directly (e.g., `execFile` in Node.js, `subprocess.run` with `shell=False` in Python) so metacharacters are treated as data, not commands.

## 12. Related Concepts
- **Input Validation:** The core defense against both these flaws.
- **Remote Code Execution (RCE):** OS Command injection is a direct path to RCE.
- **File Inclusion (LFI/RFI):** Similar to Path Traversal, but specifically involves executing or including the file's contents within the application code, not just reading it.

## 13. Important Commands / Syntax
- `../` : Traversal sequence used to move up one directory level.
- `....//` : Bypasses non-recursive stripping filters that remove `../`.
- `%252e%252e%252f` : Double URL-encoded version of `../` to evade basic filters that only decode once.
- `%00` : **Null Byte**. Used to terminate a string, bypassing file extension filters that only check the end of the filename (e.g., `payload.txt%00.png`).
- `; whoami` : Uses the semicolon command separator to execute the `whoami` command (Unix/Windows).
- `| whoami` : Uses the pipe command separator to execute the `whoami` command.

## 14. Interview Questions
1. **What is the difference between Path Traversal and OS Command Injection?**
   *Answer:* Path traversal allows an attacker to read/write arbitrary files on the filesystem. OS Command Injection allows an attacker to execute arbitrary commands on the operating system shell.
2. **How can a null byte (`%00`) bypass a path traversal filter?**
   *Answer:* If the application checks that a filename ends with a specific extension (e.g., `.png`), appending `%00.png` passes the check. However, underlying C/C++ filesystem APIs interpret the null byte as the end of the string, ignoring the `.png` and processing the malicious path.
3. **If `../` is being stripped from your path traversal payload, what is a common bypass?**
   *Answer:* Using a nested traversal sequence like `....//`. When the filter removes the inner `../`, the remaining characters collapse to form a new `../`.
4. **How do you safely execute an OS command in an application if you must use user input?**
   *Answer:* Use language-specific safe execution APIs that do not invoke a shell (e.g., `shell=False` in Python's subprocess), and pass user input as an array of arguments, not as a concatenated string.

## 16. Key Takeaways
- **Path Traversal** reads files. **Command Injection** runs commands.
- Both stem from trusting user input without proper validation or sanitization.
- Always use Burp Repeater to systematically test inputs and analyze server responses.
- Filters can often be bypassed by understanding *how* they filter (e.g., non-recursive stripping vs absolute paths).
- Prevention requires strong allowlists and avoiding unsafe APIs (e.g., avoid shell interpreters).

## 17. One-Minute Revision
When web apps dynamically load files based on user input, attackers can use Path Traversal (`../`) to escape the web root and read sensitive files like `/etc/passwd`. If simple `../` is blocked, techniques like absolute paths, `....//`, double URL encoding, or null bytes (`%00`) might bypass the filter. Similarly, when apps pass user input directly to a system shell, OS Command Injection occurs. Attackers use separators (`|`, `;`) to run their own commands, leading to full server takeover. Prevent both by strictly validating input (allowlists) and using safe APIs instead of shell execution or direct filesystem access.
