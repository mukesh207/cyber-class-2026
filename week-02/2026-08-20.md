## 🧠 Key Concepts & Definitions

| Term | Definition |
|------|------------|
| Path Traversal | Also known as directory traversal. A vulnerability that allows an attacker to read arbitrary files on the server that is running an application. |
| Null Byte Bypass | Using a null byte (`%00`) to terminate a string, bypassing file extension filters that only check the end of the filename. |
| URL Encoding Bypass | Using double or superfluous URL encoding (e.g., `%252e%252e%252f` for `../`) to bypass WAFs or basic filters that decode only once. |
| Absolute Path | A file path starting from the root directory (e.g., `/etc/passwd`) which can be used if relative traversal sequences like `../` are blocked. |
| OS Command Injection | A web security vulnerability that allows an attacker to execute arbitrary operating system (OS) commands on the server that is running an application. |
| Command Separator | Characters like `;`, `|`, or `&&` that allow executing multiple commands inline on Unix/Windows systems. |

## 💻 Commands & Tools

```bash
# Example payloads for Path Traversal
cat /etc/passwd
```

| Command / Tool | What it does |
|----------------|--------------|
| `../` | Traversal sequence used to move up one directory level. |
| `....//` | Bypasses non-recursive stripping filters that remove `../`. |
| `%252e%252e%252f` | Double URL-encoded version of `../` to evade filters. |
| `; whoami` | Uses the semicolon command separator to execute the `whoami` command (Unix/Windows). |
| `\| whoami` | Uses the pipe command separator to execute the `whoami` command. |

### 🛠️ Methodology: Solving with Burp Suite & Thought Process

**1. Identify Attack Surface (Recon)**
While browsing the lab sites, I actively looked for features that interact with the filesystem (like loading product images). I noted parameters such as `?filename=53.jpg`.

**2. Target Site Map & Isolate**
Instead of catching requests on the fly, I used the **Burp Target** tab. I reviewed the **Site Map** to locate the requests that fetched files (like images) and sent those specific requests to **Burp Repeater** (`Ctrl+R`). This allowed me to quickly iterate on payloads without relying on the browser interface.

**3. Establish a Baseline & Fuzz**
I sent the unmodified request in Repeater to see the normal response. From there, I iteratively manipulated the parameter to test different defenses:
- *Test 1 (Basic):* Replaced `53.jpg` with `../../../etc/passwd`. If the server returned the contents of the `passwd` file, the lab was solved.
- *Test 2 (Absolute Path):* If basic traversal failed (e.g., `../` was blocked or sanitized), I reasoned that the server might only be filtering relative sequences. I bypassed this by just providing the absolute path directly: `/etc/passwd`.
- *Test 3 (Nested Traversal):* If the server aggressively stripped `../`, I assumed it might not be doing it recursively. I crafted `....//` payloads so the server's stripping action would inadvertently build my exploit string.
- *Test 4 (Encoding Bypass):* When basic characters were filtered, I used Burp's **Decoder** to double-URL-encode my payloads (e.g., `%252e%252e%252f`) to sneak past front-end WAFs or basic filters that only decode once.
- *Test 5 (Null Byte & Appending):* For the lab that rigidly enforced a `.png` extension, I appended a null byte (`%00`) before the required extension (`../../../etc/passwd%00.png`). The backend processed the extension to pass validation, but the underlying OS API terminated the string at the null byte when actually fetching the file.

- **File path traversal, simple case** (Apprentice): Retrieved `/etc/passwd` via a vulnerable `filename` parameter. Payload: `../../../etc/passwd`.
- **File path traversal, traversal sequences blocked with absolute path bypass** (Practitioner): Bypassed application blocking `../` by providing an absolute path directly. Payload: `/etc/passwd`.
- **File path traversal, traversal sequences stripped non-recursively** (Practitioner): Bypassed filters that remove `../` by using `....//`. When `../` is stripped, it leaves a valid `../`. Payload: `....//....//....//etc/passwd`.
- **File path traversal, traversal sequences stripped with superfluous URL-decode** (Practitioner): Bypassed filter by URL encoding the payload twice.
- **File path traversal, validation of start of path** (Practitioner): Bypassed validation checking for expected base folder. Payload: `/var/www/images/../../../etc/passwd`.
- **File path traversal, validation of file extension with null byte bypass** (Practitioner): Bypassed `.png` extension check using a null byte. Payload: `../../../etc/passwd%00.png`.
