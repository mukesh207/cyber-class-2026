## 1. What is it?
This session dives into web application vulnerabilities, focusing on the OWASP Top 10 framework and deep-diving into **SQL Injection (SQLi)**.
- **OWASP Top 10 (2021 vs 2025)**: The industry-standard awareness document representing the most critical security risks to web applications. The 2025 preview shows shifts toward AI/LLM risks and cloud-native architectural flaws compared to the classic 2021 list.
- **SQL Injection (SQLi)**: A vulnerability where an attacker can interfere with the queries that an application makes to its database. 
- **Blind SQL Injection**: A type of SQLi where the database does not return data or errors directly to the screen, forcing the attacker to infer answers by asking True/False questions (Time-based or Boolean-based).
- **Tooling**:
  - **SQLmap**: An automated tool that detects and exploits SQL injection flaws.
  - **Dirbuster / Gobuster**: Tools used to brute-force directories and files on web servers.
  - **Curl**: A command-line tool for transferring data using various network protocols, extremely useful for manual HTTP request crafting.

## 2. Why does it happen?
- **SQL Injection**: Happens because user input is unsafely embedded directly into database queries. The database interpreter cannot distinguish between the developer's intended command and the attacker's malicious input.
- **Why OWASP evolves**: The threat landscape changes. As organizations shift to the cloud and adopt AI, new vulnerabilities emerge, prompting updates to the Top 10 list.

## 3. How does it work?

Normal Query:
```sql
SELECT * FROM users WHERE username = 'admin' AND password = 'password'
```

Injected Query (Username: `admin' OR '1'='1`):
```sql
SELECT * FROM users WHERE username = 'admin' OR '1'='1' -- ' AND password = 'password'
```
The `--` comments out the rest of the query, and `OR '1'='1'` is always true, bypassing authentication.

**Oracle vs. Non-Oracle SQLi**
- **Non-Oracle (MySQL, PostgreSQL)**: Can run queries without specifying a table. Example: `SELECT 1, version();`
- **Oracle**: Requires a `FROM` clause for every `SELECT`. It uses a dummy table called `DUAL`. Example: `SELECT 1, banner FROM v$version;` or `SELECT 1 FROM DUAL;`. Also, Oracle uses `||` for string concatenation, whereas MySQL uses `CONCAT()`.

## 4. Where is it used / found?
- **SQLi**: Found in login forms, search fields, URL parameters (e.g., `id=1`), and hidden POST requests anywhere a web app talks to a relational database.
- **Gobuster/Dirbuster**: Used in the Reconnaissance/Enumeration phase of the Kill Chain to find hidden admin panels or exposed configuration files.

## 5. How do I identify it?
- **Error-Based SQLi**: Add a single quote `'` or double quote `"` to an input. If the web page crashes or throws a syntax error, the app is vulnerable.
- **Blind SQLi**: Inject a time delay (e.g., `WAITFOR DELAY '0:0:10'`). If the server takes exactly 10 seconds longer to respond, it is vulnerable.
- **Directory Enum**: Run a tool like `gobuster dir -u http://target -w wordlist.txt`.

## 6. Hands-on / Lab Methodology
**PTG: Blind SQL using SQLmap**
- **What to observe first:** Use `curl` or browser to find parameters passed in the URL (e.g., `?id=1`).
- **Attack surface:** The backend database interacting with the `id` parameter.
- **Initial hypothesis:** The `id` parameter might be directly communicating with the database without sanitization.
- **What to test:** Use `gobuster` to map out endpoints, send a `'` using `curl` to observe delays or size changes, then run `sqlmap`.
- **How to test it safely (authorized lab):** Run `sqlmap -u "http://target/page.php?id=1" --dbs --batch`.
- **Expected result:** SQLmap identifies the injection type (Blind) and enumerates the databases.
- **How to interpret the result:** The application is vulnerable to Blind SQLi. You can now use SQLmap to extract specific tables and columns.

## 7. Failed Attempts & Why
- **What was tried:** Running `sqlmap` with a simple URL but getting no results.
- **Why it failed:** The application required authentication (a session cookie).
- **What that tells us:** SQLmap needs the same access the user has to reach the vulnerable query.
- **What to try next:** Pass the cookie using `sqlmap -u "http://target?id=1" --cookie="session=xyz"`.

## 8. Example
An attacker finds an endpoint `/search?q=shoes`. They change it to `/search?q=shoes' AND SLEEP(5)--`. The server takes exactly 5 seconds to load. The attacker confirms Time-Based Blind SQL Injection and uses SQLmap to dump the `users` table, obtaining hashed passwords.

## 9. Impact
SQL Injection can lead to total database compromise. Attackers can read sensitive data (passwords, PII), modify data, or gain Remote Code Execution (RCE) on the database server using commands like `xp_cmdshell`.

## 10. Detection
- **WAF (Web Application Firewall)**: Detects SQLi signatures like `UNION SELECT` or `' OR 1=1`.
- **Database Logs / SIEM**: Detects an unusual spike in database syntax errors or long-running queries (Time-Based Blind).

## 11. Prevention / Remediation
- **Prepared Statements (Parameterized Queries)**: The absolute best defense. They ensure the database treats user input strictly as data, never as executable code.
- **Input Validation**: Use allowlists to strictly define what input is acceptable.
- **Stored Procedures**: Can offer security if implemented without dynamic SQL.
- **Escaping**: If prepared statements can't be used, properly escape special characters.

- OSINT/Recon -> Gobuster: Directory enumeration expands the attack surface to find injection points.

## 13. Important Commands / Syntax
- `gobuster dir -u http://target.com -w /usr/share/wordlists/dirb/common.txt` (Fast directory brute-forcing)
- `curl -I http://target.com` (Fetch only HTTP headers)
- `sqlmap -u "http://target.com/page?id=1" --dbs` (List databases)
- `sqlmap -u "http://target.com/page?id=1" -D public --tables` (List tables in database 'public')
- `sqlmap -u "http://target.com/page?id=1" -D public -T users --dump` (Extract data from 'users' table)

## 14. Interview Questions
- **Q: What is the main difference in exploiting Oracle SQL compared to MySQL?**
  Oracle requires a `FROM` clause in every `SELECT` query. Attackers must use the dummy table `DUAL` (e.g., `SELECT 1 FROM DUAL`).
- **Q: Explain Blind SQL Injection.**
  It's an SQLi vulnerability where the application does not return database errors or queried data to the page. The attacker asks True/False questions by injecting logical statements or time delays.
- **Q: How do Prepared Statements prevent SQL Injection?**
  They pre-compile the SQL query structure before inserting the user data. This forces the database to treat the input purely as a literal value, not as executable SQL commands.

## 16. Key Takeaways
- OWASP Top 10 tracks the most critical web app risks; adapting over time to new tech (like AI in 2025).
- SQL Injection occurs when untrusted input is interpreted as code.
- Oracle databases require `FROM DUAL` for simple `SELECT` statements, unlike MySQL.
- Blind SQLi relies on observing behavioral changes (time delays or missing content) rather than direct data output.
- SQLmap automates the entire process of detecting and exploiting SQLi, including Blind SQLi.
- Gobuster/Dirbuster are essential for mapping the hidden structure of a web application to find injection points.
- Prepared Statements are the primary defense against SQLi.

## 17. One-Minute Revision
OWASP Top 10 is the standard for web app risks. SQL Injection (SQLi) manipulates backend queries, leading to data breaches. Oracle requires `FROM DUAL` for injected queries. If the app doesn't show database output, it's Blind SQLi, requiring True/False logic or time delays. Attackers use Gobuster to find hidden pages and SQLmap to fully automate the SQLi extraction process. The best prevention is always Prepared Statements.
