# Web Applications & Network Security Infrastructure

`[ APPLICATIONS ]` `[ NETWORK ]` `[ SECURITY ]` `[ INFRASTRUCTURE ]`

> **Course:** Cybersecurity
> **Date:** 2026-08-31 | **Session:** 08 (Week 04)

---


## 1. What is it?
In simple terms, this topic covers the rules that allow web browsers to talk to websites (**HTTP**) and the defensive shields (**Firewalls, WAFs, IDS/IPS**) that protect that communication. 

Technically, it is the layered architecture of network appliances and application-layer protocols designed to securely deliver web content. It involves routing and filtering traffic to ensure availability (via **Load Balancers** and **High Availability** setups), while detecting and mitigating malicious traffic before it reaches the web server.

## 2. Why does it happen?
Why do we need all this infrastructure? Because the internet is inherently open and hostile. Web servers must accept connections from external sources to function, which creates a massive attack surface. 
- **Security appliances** (Firewalls, IDS/IPS, WAFs) exist to filter the "bad" traffic out of this necessary open communication.
- **Security Headers** exist to protect the client (user's browser) from executing malicious code.
- **Redundancy systems** exist because single devices inevitably fail, and a single point of failure (SPOF) can take down an entire business.

## 3. How does it work?
When a user (or attacker) sends a request to a web application, it traverses a layered security architecture before reaching the application logic.

**Network Security Devices Architecture:**
```text
[User / Attacker]
       |
       v
[Gateway Router]
       |
       v
  [Firewall] ----------------> [IDS (Passive Monitor)]
       |
       v
 [IPS (Active)]
       |
       v
 [Load Balancer]
       |
       +---------> [WAF] -----> [Web Server A]
       |
       +---------> [WAF] -----> [Web Server B]
```

**High Availability (HA) Duplication:**
To avoid a SPOF, appliances use clusters:
- **Active/Passive:** One device handles all traffic. If it fails (determined by a heartbeat signal), the secondary takes over.
- **Active/Active:** Both devices handle traffic simultaneously, increasing throughput and sharing the load.

**HTTP Protocol Sequence:**
```text
[Client / Browser]                                [Web Server]
        |                                              |
        | ------ HTTP Request (GET /dashboard) ------> |
        |        Headers: User-Agent, Cookie           |
        |                                              |
        |                                              | (Processes request,
        |                                              |  validates session)
        |                                              |
        | <----- HTTP Response (200 OK) -------------- |
        |        Headers: Content-Type, Set-Cookie     |
        |        Body: <html>...</html>                |
```

## 4. Where is it used / found?
This layered defense architecture is found in every corporate enterprise network, cloud environment (AWS, Azure, GCP), and modern web application infrastructure. HTTP and security headers are used by every modern web browser to securely render websites.

## 5. How do I identify it?
**Identifying Honeypots (as an attacker):**
- Unrealistic isolation (no internal network to pivot to).
- "Too easy" exploitation (e.g., default `admin/admin` works immediately).
- Simulated or empty file systems.
- Predictable TCP/IP stack behavior when fingerprinted by `nmap` or Shodan.

**Identifying Web Protections & Headers:**
- Use browser DevTools (Network tab) or `curl -I` to view the response headers from a server (e.g., looking for `Content-Security-Policy`).
- If a payload (like `' OR 1=1 --`) gets immediately blocked with a 403 Forbidden before reaching the app logic, a **WAF** is likely in place.

## 6. Hands-on / Lab Methodology

```text
🧪 HANDS-ON
━━━━━━━━━━━━━━━━━━━━
```
When testing web applications and network defenses in an authorized lab:
- **What to observe first:** Review the HTTP response status codes (1xx Info, 2xx Success, 3xx Redirect, 4xx Client Error, 5xx Server Error).
- **Attack surface:** Port 80/443, input fields, URL parameters, and HTTP headers.
- **Initial hypothesis:** The application might not validate input securely, or a WAF might be filtering basic payloads.
- **What to test:** Use different HTTP methods (GET, POST, PUT, OPTIONS) to see how the server state changes. Check for the absence of critical security headers.
- **How to test it safely (authorized lab):** Use TryHackMe rooms (Web Application Basics, HTTP in Detail) or local VMs.
- **Expected result:** Malicious inputs should be blocked by a WAF or sanitized by the app. Missing headers will expose the site to client-side attacks.
- **How to interpret the result:** If a WAF blocks you, you must obfuscate your payload. If a honeypot traps you, recognize the fake environment and pivot away.

## 7. Failed Attempts & Why
> ⚠️ **FAILED ATTEMPTS / LESSONS LEARNED**
> 
> - **What was tried:** Scanning and exploiting an exposed SSH port on a target.
- **Why it failed (if it was a honeypot):** The system was deliberately vulnerable but completely isolated from the real corporate network.
- **What that tells us:** Attackers must verify the authenticity of a target via careful footprinting before wasting time exploiting it.
- **What to try next:** Move to other hosts, check for WAF presence on web ports, and look for real application logic.


## 8. Example
A legitimate user logs into a portal. The **HTTP POST request** passes through the **Firewall** (allowed, port 443), isn't flagged by the **IPS**, and hits the **Load Balancer**. The load balancer sends it to a backend server. The **WAF** inspects the payload and finds it clean. The server processes the login and returns an HTTP 200 OK response containing an **Anti-CSRF token** and a **Strict-Transport-Security** header to secure the user's ongoing session.

## 9. Impact
If these layered defenses fail:
- Missing Firewalls/IPS allow attackers to directly exploit internal services.
- Missing WAFs allow devastating Layer 7 attacks like SQL Injection or Cross-Site Scripting (XSS).
- Missing HA leads to downtime and Denial of Service (DoS).
- Missing Security Headers allow attackers to compromise client sessions via CSRF, Clickjacking, or MIME-sniffing.

## 10. Detection
How defenders spot the attackers:
- **IDS:** Passively monitors traffic and generates alerts for SOC analysts when known malicious signatures are seen.
- **WAF:** Logs malicious payloads aimed at the web application (e.g., `<script>` tags in input fields).
- **Honeypot:** Generates high-fidelity alerts. Because legitimate users have no reason to access a honeypot, *any* interaction is highly suspicious and indicative of a scan or attack.

## 11. Prevention / Remediation
To secure the infrastructure:
- Implement **Active/Active** or **Active/Passive** redundancy to prevent Single Points of Failure.
- Deploy a **WAF** with an updated rule set (like the OWASP ModSecurity Core Rule Set) to filter Layer 7 attacks.
- **Developers must enforce Security Headers:**
  - **Content-Security-Policy (CSP):** Prevents XSS by defining allowed script sources.
  - **Strict-Transport-Security (HSTS):** Forces HTTPS, preventing SSL stripping.
  - **X-Frame-Options:** Prevents Clickjacking (`DENY` or `SAMEORIGIN`).
  - **Anti-CSRF Tokens:** Secure POST requests against Cross-Site Request Forgery.

## 12. Related Concepts
**Networking Basics -> Ports & Protocols (TCP/UDP) -> HTTP Protocol -> Layered Defense (Firewalls/WAFs) -> Secure Web Applications.** 
Understanding the underlying network layers (OSI Model) is crucial because firewalls operate at Layers 3/4, while WAFs and HTTP operate at Layer 7.

## 13. Important Commands / Syntax
- `curl -I https://example.com`
  - Fetches only the HTTP headers (HEAD request) to inspect security headers quickly.
- `nmap -sV <IP>`
  - Scans for open ports and determines service versions; helpful for identifying outdated services deliberately placed in a honeypot.

## 14. Interview Questions
1. **What is the difference between an IDS and an IPS?** 
   - An IDS is passive (out-of-band); it monitors and alerts. An IPS is active (in-line); it can proactively block malicious packets.
2. **Why do we use WAFs if we already have a network firewall?** 
   - Network firewalls filter based on IPs and ports (Layers 3/4). A WAF inspects the actual HTTP payload (Layer 7) to block application-specific attacks like SQL injection.
3. **What is a honeypot and how might an attacker detect one?** 
   - A decoy system meant to trap attackers. Attackers might detect it via unrealistic network isolation, vulnerabilities that are "too easy" to exploit, or distinct TCP/IP stack fingerprints.
4. **What does the HSTS header do?** 
   - Strict-Transport-Security forces a browser to interact with the site *only* over HTTPS, which prevents downgrade attacks like SSL stripping.

## 16. Key Takeaways
> 💡 **KEY TAKEAWAYS**
> 
> - **Layered Defense:** No single appliance does everything. Firewalls (L3/L4), IPS, and WAFs (L7) work together.
> - **Redundancy:** High Availability (HA) setups eliminate Single Points of Failure.
> - **Honeypots:** Decoy systems gather threat intelligence but must be believable to trap skilled attackers.
> - **HTTP:** Operates via a Request/Response cycle where headers control crucial security behaviors.
> - **Security Headers:** CSP (XSS defense), HSTS (HTTPS enforcement), and X-Frame-Options (Clickjacking defense) are mandatory for modern web apps.
>

## 17. One-Minute Revision

```text
⏱️ ONE-MINUTE REVISION
━━━━━━━━━━━━━━━━━━━━━━
```
Web security relies on a layered architecture. The Gateway Router routes traffic. The Firewall blocks unauthorized ports. The IPS blocks known malicious packets. The Load Balancer ensures availability. The WAF blocks Layer 7 web attacks (like SQLi). Redundant setups (Active/Passive) prevent total network failure. Honeypots act as decoys to waste attacker time and gather intelligence. Finally, legitimate traffic reaches the web server, which responds with critical Security Headers (CSP, HSTS) to protect the user's browser from executing malicious client-side attacks.
